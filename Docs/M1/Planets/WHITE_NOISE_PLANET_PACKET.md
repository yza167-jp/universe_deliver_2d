# Planet Packet — White Noise / 白噪星

## Canon status

- 冰原、冰洞、极光、电磁暴雪、较强重力、记忆档案文明与特高压电屏蔽罩：PROVISIONAL 框架已批准用于 M1。
- 角色显示名、物种、货物显示名和聚落名：候选制，未锁定。

## One-sentence identity

一颗被电磁暴雪覆盖的冰封星球，其地下文明将记忆保存视为公共基础设施，却正因“谁有权决定永久保存什么”而分裂。

## Narrative role

- 第二颗完整星球，验证 M0 架构可扩展。
- 第一次使用剧情必需模块。
- 将中继网与跨世代档案联系起来。
- 引入关系、许可、图鉴和正式支线循环。

## Natural environment

- 相对重力工作范围：1.2–1.35。
- 表面：冰原、裂谷、冰洞入口、极光。
- 天气：高压电磁暴雪、低能见度、静电放电。
- 地下：较稳定的档案层、透明/半透明材料与冰中光带。
- 光照：外部冷白/深蓝，地下使用暖白档案光和极光反射。

## Civilization

- 生活在冰层下，以保存、校验和继承记忆为核心。
- 记忆既是私人经验，也是历史、技术和公共责任。
- 档案维护者承担“长期保留成本”，不把无限保存视为天然善。
- 公司试图把索引和访问权包装为跨文明档案服务。

候选文明/聚落称呼：

1. **推荐工作候选：** 静层档案区 / Still-Layer Archives
2. 冰下记忆库 / Under-Ice Memory Vaults
3. 白噪共存层 / White Noise Continuity Layer

## Local conflict

一套关键档案索引损坏。公司要求恢复并接入商业服务，当地不同角色则争论：索引是否会暴露私人记忆、谁有权授权、删除是否也可能是一种保护。

## Flight identity

T-120 灰盒阶段：

```text
轨道/高空接近
→ 开阔冰原
→ 冰裂谷/冰洞三路分流
→ 极光与电磁暴雪视觉占位
→ 地下档案入口
→ 最终进场与档案平台着陆
```

独特机制：

- 较强重力要求更早拉起。
- 电磁干扰影响导航稳定、部分 HUD 和提示，不直接反转控制。
- 屏蔽罩降低干扰持续时间/强度与资源风险。
- 路线提示与高对比模式在暴雪中必须有效。

T-120 已实现基线：

- 独立 `34000 m` 六段路线，名义快速/常规/观景时长
  `88 / 118 / 154 s`，不复用赤砂八阶段、雷达或沙漠危险。
- `10000–17000 m` 冰裂谷提供上层快速、中层常规、下层观景三条可碰撞局部
  通道，在极光区前汇合；每条通道有安全重试 Y。
- `gravity_scale = 1.28` 作为唯一星球权威，六个环境 profile 对齐到
  `256 px/s²`；继续使用 M0 飞船、辅助、资源、碰撞、检查点和诊断合同。
- 极光、电磁暴雪、冰层、档案门与有限平台仍是 production placeholder；
  T-121 已接入确定性电磁干扰、屏蔽差异与低能见度资源风险，正式背景/VFX/音频
  打磨继续属于 T-123。
- 仅 `--m1-debug=white_noise_route` 可直达；正式星球与订单仍为
  `REGISTERED_ONLY`，没有普通玩家出发路径。

T-111 实现基线：

- 只有已安装的 `capability_high_voltage_shielding` 才参与危险计算；仅拥有模块
  不能替代出发前安装检查。
- 高压资源伤害暂乘 `0.60`，电磁干扰暂乘 `0.45`，数值集中在模块 Resource，
  白噪路线不得再复制硬编码。
- 高压伤害缩放后继续进入普通护盾优先入口；模块不会创建独立护盾条或完全免疫。

T-121 实现基线：

- `17000–23000 m` 使用固定、无随机的
  `CLEAR → WARNING → ACTIVE → RECOVERY` 暴雪状态；最短时长
  `2.4 / 12.0 / 2.8 s`，短倒车不回滚，Boost 不跳过预警。
- 活跃期每 `4.0 s` 请求一次 `18` 高压伤害；屏蔽后的实际请求为 `10.8`，
  干扰由 `0.86` 降为 `0.387`。伤害继续护盾优先，不提供完全免疫。
- 暴雪只影响局部可见度、非核心提示更新与入口信标清晰度；核心资源 HUD 和玩家
  控制持续有效。路线提示、高对比与慢动作使用既有辅助设置。
- 已安装和未安装的隔离调试入口可比较同一序列；正式白噪星与订单继续
  `REGISTERED_ONLY`。

T-122 内容基线：

- `order_m1_white_noise_archive_core`、`cargo_white_noise_archive_core` 与
  两个角色 stable ID 保持不变；订单、货物和角色显示名继续为候选，
  `PROVISIONAL` 状态没有升级。
- 出发前订单详情同时显示公司“标准档案服务组件”记录和“冷核可能带来批量访问
  接口”的实际用途；五条客户历史明确索引事故、最小访问、家庭/个人记忆与现场
  授权责任。
- 驾驶舱用四套独立对白覆盖强重力、电磁暴雪、公司广播、当地最小访问封签和
  “记忆片段不等于整个人”；公司终端与货舱面板保持两种具体表述，而不是百科式
  总结。
- 本任务不加入目的地选择、不决定公开结果，也不揭示中继网创造者；这些继续由
  T-124/T-125 落地。正式订单与星球仍为 `REGISTERED_ONLY`。

T-123 production placeholder 基线：

- 七层路线呈现使用深海蓝高空、冻结星球弧、远/中景冰层、可碰撞冰面、半透明
  裂谷、绿粉极光和冰下档案光栅；黄色只作为高对比航标/碰撞强调，和赤砂铁锈红
  沙漠保持截图级区分。
- 极光暴雪以程序绘制辉光、高压弧、世界雪线和屏幕电磁干扰叠加；高对比辅助
  同时降低雪粒、噪声线与脉冲闪光，不能只把地形边缘改色。
- 场景局部环境反馈运行时合成安全冰风、暴雪静电、地下档案机械三层循环与短
  记忆动机。当前全部是项目原创 production placeholder，不是最终商业美术或
  完整配乐。
- 三路分流、可碰撞上缘、路线提示和有限平台轮廓优先于装饰层；正式星球与主线
  订单仍为 `REGISTERED_ONLY`，T-124/T-125 才接通目的地与完整开放。

## Arrival scene

- 冰下档案区 1–2 屏。
- 主要 NPC、索引终端、可选记忆持有人。
- 玩家选择最小公开索引、保持封存或交给当地共同保管。
- 所有选择推进主线；影响关系、许可、图鉴和后续对白。

T-124 已将该包落成 `1.5` 屏、`960×360` 的冰下档案灰盒：

- 交付座、档案维护者、最小访问索引终端、记忆持有人代理和返航升降梯共用
  `StationPlayer`、`Interactable2D` 与 `SceneModalCoordinator`；主对话锁定世界
  输入，终端/设备观察保留移动并抑制重复提示。
- 核心 NPC 的主对话包含失效索引目标、记录马达声与霜纹的日常细节，以及
  “运输必要但批量访问未获授权”的公司立场；目的地说话人显示职务称谓，正式
  候选角色 Resource 与最终显示名仍保持 `PROVISIONAL`。
- 三个局部选择分别写入最小公开索引、保持封存、本地共同保管的稳定剧情标记，
  然后汇入同一探索与返航升降梯；T-124 不发信用点、关系、许可、图鉴或完成
  订单，统一奖励结算属于 T-125。
- 索引终端取得的中继片段只证明协议修订记录比公司接口早 `37` 年；它不说明
  创造者、真实用途或老皮来源。正式白噪订单与星球在 T-125 前继续
  `REGISTERED_ONLY`。

## Revisit seed

- 档案是否对外开放。

- 记忆持有人后续状态。
