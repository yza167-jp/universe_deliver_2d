# M1 Systems Delta / M1 系统增量

本文只描述相对 M0 的新增或扩展。M0 已通过的飞行、模态、伤害、检查点、存档备份与场景流合同默认保持。

## 1. 存档与进度

新增：

- schema v2 与 v1 迁移。
- `main_story_chapter`。
- `unlocked_planet_ids`。
- `planet_relation_values`。
- `planet_permission_ids`。
- `codex_entry_ids`。
- `souvenir_ids`。
- `completed_side_order_ids`。
- `station_state_level` / `station_upgrade_ids`。
- `ship_upgrade_ids`。
- `revisit_state`。
- `demo_ending_flags`。

不新增多存档槽、云存档或飞行节点序列化。

上述字段的运行时真相仍在 `GameStateModel`。章节、星球、关系、许可、图鉴、
纪念品和回访统一通过公开 API 修改；`M1ProgressRules` 只提供无状态白名单与准入
评估，`SaveService` 继续捕获同一批 schema v2 字段。

## 2. 多星球导航

- 导航由 PlanetDefinition、章节、许可和模块共同决定。
- 未解锁星球可以显示轮廓与解锁原因，但不能选择。
- 主线顺序默认固定：赤砂回访 → 白噪 → 穹林 → 群潮。
- 支线只在对应章节和关系条件满足时显示。
- 驾驶舱仍不自由驾驶星图。
- 当前白噪准入要求已到白噪章节、赤砂已解锁且拥有或安装特高压电屏蔽罩；穹林与
  群潮各要求前序章节和前一颗星球，不允许越级解锁。

## 3. 订单模型

- 一次仍只允许一份 active order。
- `OrderDefinition` 增加 `MAIN / SIDE / REVISIT`、`LANDING /
  LOW_ALTITUDE_DROP`、章节与解锁条件、加急参数、关系/许可/图鉴/纪念品奖励及
  `UNIQUE / REPEATABLE / ARCHIVED_ONLY` 重复策略。
- 持久状态统一为 `AVAILABLE / ACCEPTED / COMPLETED / FAILED / ABANDONED /
  ARCHIVED`；只有 `ACCEPTED` 占用 active order 槽位，存档中也只允许一个
  `ACCEPTED`。
- 主线与回访订单不可误放弃；失败时保持 `ACCEPTED`，由既有检查点/重试流程继续，
  不制造主线死档。
- 支线可放弃、失败或以降低报酬的完成结果表达部分成功。`REPEATABLE` 只允许
  `FAILED / ABANDONED → ACCEPTED` 的显式重接；任何 `COMPLETED` 订单都不能再次
  接取或重复发奖。
- `ARCHIVED_ONLY` 用于只记录历史而不进入 active order 的条目，不是可接任务。
- 支线失败不撤销主线章节、模块或星球资格。
- 接受条件统一消费 T-102 的章节、星球、许可和模块状态；订单完成通过
  `GameStateModel` 的单一入口原子应用信用点、关系、许可、图鉴、纪念品和完成
  标记，并写入奖励幂等账本。
- 不建立随机刷新、每日任务或无限委托板。

## 4. 支线计时与报酬

加急支线可以配置：

```text
target_seconds
grace_seconds
minimum_reward_ratio
relation_bonus_on_time
```

规则：

- 只有 active 的加急订单累计 `OrderRunState.elapsed_time`；非加急订单不累计。
- `elapsed_time <= target_seconds` 时保留全额信用点及准时关系奖励；随后在
  `grace_seconds` 内线性降至 `minimum_reward_ratio`，继续超时也不低于该下限，
  不直接硬失败。
- 对话、帮助面板和系统暂停均暂停计时。
- 检查点重试保留同一计时；完成后由 `reward_applied_order_ids` 阻止重复增加奖励。
- 非加急订单不显示倒计时压力。

## 5. 第二种正式交付：低空投放

M1 的低空投放先使用固定、宽容接收区：

- 玩家进入高度、速度和水平位置窗口。
- 按统一 Input Map action 释放货物。
- 成功：落入核心接收区。
- 部分成功：落入外圈，降低报酬/关系。
- 失败：错过区域或货物损坏，可重试或放弃支线。
- 投放后同一货物不可重复释放。
- 不做军事投弹、复杂弹道或移动敌对目标。

首次正式使用：穹林星支线“孢子季急投”。

## 6. 关系、许可与玩家方式

关系值是小型叙事状态，不是可刷声望条。

影响：

- 后续对白。
- 部分支线和回访入口。
- 许可或便利路线。
- 图鉴文本。
- Demo 结尾变量。

来源：

- 主线局部选择。
- 支线结果。
- 武器封存/保留。
- 货物状态和交付方式。

不得通过重复同一订单无限刷关系。

M1 运行时关系范围集中为 `-2…+3`。每次正常关系变化携带唯一事件 ID，已应用事件
随 `story_flags` 保存；重复事件、到达边界后的无效变化和重复许可均不再次发出
持久化变更。

## 7. 飞船成长

### 特高压电屏蔽罩

- 白噪星主线资格模块。
- 降低电磁干扰和高压环境风险。
- 不替代普通护盾资源。
- 由赤砂回访确定获得。

### 生物信号隔离舱

- 降低穹林星货物吸引生物的范围/频率。
- 不使玩家完全免疫生态风险。

### 横风稳定器

- 降低群潮星横风扰动。
- 不自动驾驶、不取消风向判断。

配置界面继续保持少量明确槽位；不引入随机品质与复杂科技树。

## 8. 快递站成长

### 档案终端

- 赤砂回访后解锁。
- 查看人物、星球、货物和异常记录。

### 生态角

- 穹林星后解锁。
- 提供生活感、角色对话和纪念品展示。

### 中继观测室

- 群潮星结尾解锁。
- 承担 Demo 最终中继信号和星图外坐标。

站点变化以可见场景和新互动为主，不发展成资源经营模拟。

## 9. 星球独特机制扩展方式

核心飞船脚本不得堆叠 `if planet_id == ...`。

推荐：

- `FlightEnvironmentProfile`：重力、阻力、风、能见度。
- 小型危险组件：电磁干扰、生态吸引、横风区域。
- `FlightRouteDefinition`：阶段、检查点、背景和交付目标。
- 模块 capability tags：环境适应能力。
- 独立纯逻辑模型：可自动测试的危险与判定。

M0 的统一伤害、HUD、帮助、重试和 SceneRouter 继续复用。

## 10. 星球系统摘要

| 星球 | 核心环境 | 独特机制 | 关键模块 | 交付 |
|---|---|---|---|---|
| 赤砂回访 | 沙漠与维修场变化 | 短回访路线/剧情改装 | 取得屏蔽罩 | 着陆 |
| 白噪 | 强重力、电磁暴雪、低能见度 | 干扰与屏蔽 | 特高压电屏蔽罩 | 着陆 |
| 穹林 | 低重力、树洞、孢子、生物群 | 武器封存、货物吸引生态 | 生物信号隔离舱 | 着陆 + 低空投放 |
| 群潮 | 横风、海面、岛屿、天气塔 | 风向与塔控制区 | 横风稳定器 | 浮动平台着陆/简化对接 |

## 11. 图鉴与纪念品

基础类别：

- 星球。
- 人物。
- 货物。
- 纪念品。
- 异常信号。

原则：

- 未解锁条目不剧透。
- 图鉴记录人物和选择结果，而非只列百科。
- M1 不要求 100% 收集。
- 约 95% 隐藏结局属于完整游戏远期，不在 M1 实现。

## 12. M1 回归合同

每个重要提交至少保护：

```text
M0 新游戏与继续
M0 赤砂首单
v1 → v2 迁移
一次一单约束
模态 UI 与输入恢复
飞行伤害与检查点
赤砂 canonical AGL
存档主档/备份
```

每颗新星球应提供：

- 场景实例化测试。
- 路线阶段与检查点测试。
- 独特机制纯逻辑测试。
- 订单从接取到结算的烟雾。
- 直接调试入口。
