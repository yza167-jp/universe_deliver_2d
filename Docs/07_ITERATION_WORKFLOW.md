# 07 — Iteration Workflow / 迭代工作流

## 1. 目标

工作流服务于两件事：

- Codex 快速实现小而完整的可玩增量。
- 人类在综合节点直接试玩和判断，而不是被迫填写庞大证据系统。

自动检查负责“工程和状态合同成立”；人工试玩负责“是否好玩、好读、好听、像一个具体星球并让人想继续”。两者不能互相冒充。

## 2. 当前任务入口

当前里程碑是 M1。活动任务队列为：

```text
M1_DEVELOPMENT_TASKS.md
```

根目录 `DEVELOPMENT_TASKS.md` 是 M0 已完成历史，不再从其中领取任务。

每次会话按顺序：

1. 阅读 `AGENTS.md`。
2. 阅读 `CODEX_GOAL.md`。
3. 阅读 `M1_DEVELOPMENT_TASKS.md`。
4. 阅读当前任务引用的 `Docs/` 和 `Docs/M1/` 文档。
5. 运行 `git status --short`。
6. 查看近期相关提交和当前实现。
7. 确认依赖、M0 回归影响和工作区用户修改。
8. 将唯一当前任务改为 `In Progress`。

若存在 `In Progress` 或 `Human Check`，不得领取新任务。

开始报告只需说明：

- 当前阶段和任务。
- 玩家价值。
- 范围与明确不做。
- 依赖和 M0 回归影响。
- 预计运行的验证。

不要重复整份设计文档，也不要重新询问仓库已经回答的问题。

## 3. 标准实现循环

```text
读取任务与现状
→ 检查 M0 基线影响
→ 找到最小可逆实现
→ 修改数据/代码/场景
→ 运行当前任务快速检查
→ 启动最短可玩路径
→ 根据真实结果修正
→ 更新测试和必要文档
→ 运行完整适用检查与 M0 回归
→ 更新任务/阶段状态
→ 主 Agent 提交
→ 报告并停止
```

一次只做一个任务。新任务被解锁后也不能在同一轮继续实现。

## 4. 检查层级

### Level 0 — 编辑中快速检查

适合每次小修改：

- 编辑器/语言服务器错误。
- 相关单元测试。
- 当前数据验证。
- 当前场景直接运行。

### Level 1 — 仓库检查

完成任务前运行：

```bash
./scripts/check_project.sh
```

预期包括：

- Godot 版本检查。
- Headless import。
- GDScript 解析。
- 测试运行器。
- 关键场景烟雾。
- `git diff --check`。

### Level 2 — 当前增量烟雾

根据任务运行：

- schema/状态任务：迁移 fixture、保存、重建 App、继续游戏。
- 导航/订单任务：从稳定快递站状态进入对应面板并验证状态。
- 星球数据任务：注册表、本地化和引用验证。
- 路线任务：直接进入当前星球路线或检查点。
- 到达/结算任务：从合法订单结果进入到达场景并返站。
- 支线/投放任务：成功、部分成功、失败和放弃路径。

### Level 3 — M0 回归

以下共享区域被修改时必须运行 M0 完整闭环：

- `GameState`、SaveService、schema 或数据注册表。
- SceneRouter 与阶段切换。
- 对话、模态协调和通用互动。
- 飞船、资源、伤害、HUD、检查点或交付接口。
- 大厅、驾驶舱或共用到达/结算流程。

M0 回归至少覆盖：

```text
新游戏
→ 赤砂接单与配置
→ 驾驶舱旅行
→ 飞行失败/重试与着陆
→ 维修场剧情
→ 结算返站
→ 保存、重建 App、继续游戏
```

### Level 4 — M1 Human Check

只在综合节点执行完整试玩：

- Gate E：白噪星垂直切片。
- Gate F：成长、支线、低空投放和赤砂回访。
- Gate G：穹林星。
- Gate H：群潮星高潮。
- Gate I：M1 四星 Demo 完整闭环。

到达 Gate 后停止扩范围。详细路径见 `Docs/12_M1_ITERATION_GATES.md`。

## 5. M1 内容生产循环

每颗新星球按以下顺序：

```text
Planet Packet
→ Order Packet
→ Character Packet
→ Resource 与本地化数据
→ 路线灰盒和环境参数
→ 独特危险/机制
→ 驾驶舱与到达剧情
→ 结算、关系、许可和回访种子
→ 视听占位
→ 自动回归
→ Human Check
```

未完成 Planet Packet，不投入高成本最终资产；内容状态仍为 `PROVISIONAL` 时，不得自行写成 LOCKED 正史。

## 6. 人工试玩包

主 Agent 提供：

```markdown
## Build / Commit
<commit hash>

## How to run
<exact command>

## Save / Start State
<new game / migrated save / fixture>

## Expected play time
<rough range>

## Route
1. ...
2. ...

## Focus questions
1. ...
2. ...

## Known limitations
- ...

## Reset / retry
<keys or steps>
```

反馈可以是自然语言。主 Agent负责整理到任务、Decision Log 和对应内容包，不要求用户填写大型表格。

## 7. 飞行与星球机制调参

任何新星球飞行改动：

1. 先在固定路线或局部实验场验证。
2. 保持 M0 赤砂基线参数不变。
3. 一次只改变一组相关参数。
4. 比较当前星球与赤砂基准。
5. 测试默认辅助、无辅助和必要的高辅助状态。
6. 测试正常路线、危险路线、失败和检查点。
7. 再决定是否提升为星球默认值。

避免一次同时修改重力、推力、相机、路线长度和危险密度，导致无法判断原因。

## 8. 任务状态

### `Done`

只有在：

- 范围实现。
- 验收标准满足。
- 自动检查通过。
- 必要 M0 回归通过。
- 非人工 Gate 或人工 Gate 已明确接受。

时使用。

### `Human Check`

自动检查已通过，但需要用户判断。主 Agent不得自行改成 Done，也不得领取下一任务。

### `Blocked`

必须说明具体依赖或真实错误。不要用 Blocked 代替排查。

### 发现额外问题

- 阻塞当前验收：在当前任务/Gate 修复。
- 非阻塞小问题：记录为后续任务或已知限制。
- M2+ 想法：写入 Scope 或 Decision Log，不顺手实现。

## 9. Git 工作方式

### 提交者

- 仅主 Agent 提交。
- 子 Agent可研究或修改隔离工作区，但不提交。

### 提交时机

- 一个任务或可解释增量完成。
- 检查与必要 M0 回归通过。
- 任务状态已更新。
- 不包含无关用户改动。

### 提交信息

优先中文、动词开头：

```text
建立 M1 存档迁移与章节状态
实现白噪星特高压电屏蔽门槛
加入赤砂星回访与低空投放支线
实现穹林星生态航路压力
完成群潮星天气塔高潮流程
```

避免：`update`、`fix stuff`、`WIP`、`final`。

### 提交前清单

```bash
./scripts/check_project.sh
git diff --check
git status --short
git diff --stat
```

核对：

- 没有 `.godot/`、日志、导出构建和本机临时文件。
- 外部素材已更新 `ATTRIBUTION.md`。
- 新依赖已更新 Dependency Log。
- 玩家文本没有长段硬编码。
- M0 回归结果已记录。
- 没有无关重构。

## 10. 新依赖流程

1. 描述具体问题。
2. 尝试 Godot 内置能力或小型自有实现。
3. 比较候选依赖。
4. 在 `Docs/09_DEPENDENCY_LOG.md` 记录。
5. 仅在理由充分时安装。
6. 限制使用范围并写移除方案。
7. 运行完整检查与 M0 回归。

不要为了省少量代码引入会长期控制内容或存档格式的大型插件。

## 11. 文档维护

- 产品事实改变：更新 Narrative Bible、Game Vision、M1 Decisions 和 Decision Log。
- M1 范围改变：更新 CODEX_GOAL、Demo Scope、Roadmap 和任务队列。
- 技术合同改变：更新 Technical Design / M1 Technical Delta 和 Decision Log。
- 星球内容改变：更新 Planet/Order/Character Packet。
- 任务实现细节：优先由 Git 表达，只在任务中记录结果与 Gate 反馈。
- 新第三方内容：更新 Attribution / Dependency Log。

README 保持入口性质，不堆叠所有任务日志。

## 12. 常见问题处理

### M0 回归失败

- 不通过更新基线或删除测试解决。
- 先确认 M1 是否真的需要改变共享合同。
- 优先增加兼容路径或星球局部实现。
- 无法保持基线时停止并请求明确设计决定。

### 新星球像换皮

- 检查 Planet Packet 是否同时改变自然、人文、冲突、货物、飞行、角色和视听。
- 不用增加障碍数量代替独特机制。
- 在对应 Gate 前停止继续制作下一星球。

### 内容规模膨胀

- 回到 Planet Packet 的 Scope Budget。
- 复用路线阶段、短支线和场景状态。
- 删除不服务主线或角色的系统。
- 不用程序生成掩盖内容设计不足。

### 自动测试通过但体验不成立

- 自动测试只证明合同。
- 在当前 Gate 返工最小问题。
- 不扩展下一内容层。

## 14. 不采用的流程

本项目不建立庞大的人工证据录入、几十项截图门槛或为了验证而验证的工具链。

只保留：

- 一个快速仓库检查入口。
- 有价值的自动测试。
- M0 回归合同。
- 简洁人工试玩包。
- 清楚的 Git 历史。
- 关键决策和内容包。

工具只在明显减少重复劳动时新增。
