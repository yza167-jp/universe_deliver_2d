# 04 — Demo Scope / Demo 范围

## 1. 为什么分成 M0 与 M1

用户希望第一版就具备快递站、三到四颗星球、飞船和订单系统。这个目标定义为正式可对外试玩的 **M1：Four-Planet Demo**。

但在数天内让 Codex 同时搭建四颗星球，会导致每套系统都只有表面、飞行手感无法验证、剧情与美术重复返工。因此先制作一个内部 **M0：Playable Spine**，用一颗赤砂星打通所有层级，再逐颗扩展。

M0 不削减 M1，它是 M1 的技术和体验准入门槛。

## 2. 产品阶梯

| 里程碑 | 目的 | 内容规模 | 对外定位 |
|---|---|---|---|
| M0 Playable Spine | 证明完整游戏结构成立 | 1 站、1 船、1 星、1 主线订单 | 内部试玩 |
| M1 Four-Planet Demo | 展示游戏的内容差异与主线弧线 | 1 站、1 船、4 星、少量支线 | 可分享 Demo |
| M2+ Full Game | 扩展主线、支线、回访与结局 | 更多主/支线星球、终局系统 | 后续决定 |

## 3. M0 — Playable Spine

### 3.1 玩家流程

```text
主菜单
→ 边境快递站醒来/上班
→ 老皮引导移动和互动
→ 查看赤砂星订单
→ 查看客户历史和货物
→ 配置唯一飞船，可选安装激光炮与护盾备用电源
→ 进入第一人称驾驶舱
→ 设置赤砂星目的地
→ 宁静航行与老皮对话
→ 横版飞行：星系外缘
→ 陨石带
→ 近轨道与星球放大
→ 大气边缘
→ 雷暴
→ 低层沙漠、设施与低空管制雷达（低飞危险）
→ 无雷达高位着陆准备
→ 从高处下降的宽容着陆
→ 场景式交付对话
→ 小型可步行维修场
→ 订单结算
→ 返回变化后的快递站
→ 保存并继续
```

### 3.2 内容预算

| 内容 | M0 预算 |
|---|---|
| 快递站 | 1 个大厅，2–3 屏面积 |
| 伙伴 | 老皮 1 名，贯穿全流程 |
| 星球 | 赤砂星 1 颗完整可进入 |
| 订单 | 1 份主线订单 |
| 货物 | 1 件剧情货物 |
| 星球 NPC | 1 名主要 NPC + 可选环境互动 |
| 驾驶舱事件 | 1 个必触发、2 个可选 |
| 飞行时长 | 单颗主线星球进入目标约 1–3 分钟；快速 60–100 秒、常规 90–150 秒、观景 120–180 秒 |
| 到达区域 | 场景对话 + 1–2 屏小区域 |
| 交付方式 | 着陆 |
| 危险 | 固定陨石、固定雷暴、峡谷、雷达 |
| 可选模块 | 1 个激光炮模块，只打陨石；1 个护盾备用电源，仅在非 Boost、非倒车时缓慢恢复护盾 |
| 升级 | 至少 1 次确定升级或站点变化 |
| 存档 | 单一自动/继续存档 + 安全备份 |
| 辅助 | 慢动作、路线提示、高对比地形、辅助驾驶 |

### 3.3 M0 预期时长

首次完整体验目标约 20–40 分钟，取决于对话阅读、失败次数和观景方式。

M0 不以“内容时长”衡量成功，而以以下问题衡量：

- 玩家是否愿意继续了解老皮？
- 是否愿意飞向下一颗星球？
- 星球进入是否有仪式感？
- 飞行是否有重量但不挫败？
- 赤砂星是否像有文明的地点？

### 3.4 M0 美术标准

允许：

- 生成式像素占位图。
- 免费且许可证明确的占位素材。
- 几何灰盒、简化 Sprite、基础动画。

必须：

- 统一内部像素规格。
- 清晰的前景/碰撞层与背景层。
- 推进、Boost、碰撞、雷暴和入大气基本粒子。
- 引擎、危险、交付和环境基础音效。
- 赤砂星与空间站明显不同的色彩和氛围。

不要求：

- 最终角色立绘。
- 最终逐帧动画。
- 完整配音。
- 最终 UI 品牌设计。

### 3.5 M0 完成门槛

详见 `CODEX_GOAL.md` 与 T-055。未通过完整流程人工验收，不得启动 M1 新星球批量制作。

## 4. M1 — Four-Planet Demo

### 4.1 Demo 目标

M1 要证明游戏不只是“赤砂星的一次性概念”，而是能够让不同自然环境、文明、角色和飞行机制产生连续主线。

Demo 应具有：

- 明确序章、发展、高潮和悬念结尾。
- 四颗可进入主线星球。
- 至少一次回访或旧角色状态变化。
- 初步飞船升级与快递站变化。
- 少量支线，展示自由探索而非刷取。
- 古老中继网的第一层明确揭示。

### 4.2 四星主线顺序

1. 赤砂星：教程、公司档案矛盾、低空管制雷达。
2. 白噪星：高压屏蔽、记忆档案文明、较强重力。
3. 穹林星：生态文明、武装态度、树冠飞行。
4. 群潮星：岛屿城邦、天气控制、Demo 高潮。

### 4.3 星球内容最低包

每颗 M1 主线星球至少包含：

- 1 条完整进入/配送路线。
- 1 份主线订单。
- 1 件专属剧情货物。
- 1 个独特环境/文明飞行机制。
- 1–2 名核心 NPC。
- 1 个小型目的地区域或高质量场景式交付。
- 1 个纪念品/图鉴条目。
- 1 个可回访变化种子。
- 独立色彩、背景层、环境音和主题音乐变化。

### 4.4 四星差异矩阵

| 星球 | 自然 | 人文 | 独特飞行 | 叙事问题 | 模块/配置 |
|---|---|---|---|---|---|
| 赤砂 | 沙漠峡谷、尘暴 | 采掘殖民地与居民 | 低空管制雷达、高位着陆、雷暴 | 生存资源与公司配额 | 激光可开陨石路，基础防护 |
| 白噪 | 冰原、冰洞、电磁暴雪 | 记忆档案文明 | 低能见度、较强重力、电磁干扰 | 谁决定记忆被保存 | 特高压电屏蔽罩 |
| 穹林 | 巨树、孢子、飞行生物 | 树冠生态文明 | 树洞、垂直通道、货物吸引生物 | 运输与生态边界 | 武器状态影响通行/信任 |
| 群潮 | 海洋、岛屿、潮汐、风暴 | 岛屿城邦与天气塔 | 横风、海面低飞、移动平台 | 谁控制天气和航路 | 防风/导航模块或剧情许可 |

### 4.5 M1 订单与支线预算

建议最低：

- 主线订单：4–6 份。
- 支线订单：每颗 1–2 份，不必全部拥有独立长关卡。
- 回访：至少 1 颗星球有明显二次访问。
- 驾驶舱对话：每次主线旅行至少一个新内容。
- 快递站：至少三次可见状态变化。

支线可通过以下方式控制成本：

- 复用已有路线的不同阶段或分支。
- 使用不同货物限制和交付方式。
- 用新的 NPC/广播/小区域改变意义。
- 不简单反向跑同一关卡。

### 4.6 M1 新增系统

在 M0 基础上允许加入：

- 低空投放作为第二种正式交付方式。
- 简单支线加急订单和超时减报酬。
- 更完整的飞船数值与模块升级。
- 快递站功能/视觉升级。
- 星球关系或通行许可。
- 图鉴和纪念品墙基础版本。
- 武装/和平倾向的角色反馈。
- 局部剧情选择与 Demo 结尾变量。

仍不加入：

- 完整敌人战斗。
- 多飞船购买。
- 程序生成路线。
- 多单同时配送。
- 复杂贸易。

### 4.7 M1 时长

工作目标约 2–4 小时首次主线体验，另有少量支线和回访。此为范围估计，不是承诺；质量优先于人为拉长时长。

## 5. M2+ 远期方向

以下只保留愿景，不进入当前任务：

- 更多主线与支线星球。
- 可选海盗追逐/护航，但不得吞噬叙事核心。
- 多种交付动作。
- 更深入的飞船与站点长期成长。
- 主线结局与 95% 图鉴隐藏结局。
- 主线后持续订单和宇宙秘密探索。
- 可能的站点迁移/受损剧情。
- 多平台发行。

## 6. 范围变更规则

任何新功能先判断属于：

- **M0 必要：** 缺少它无法验证完整脊柱。
- **M0 打磨：** 改善核心但可在灰盒完成后加入。
- **M1 必要：** 用于展示多星差异。
- **远期：** 不影响 M0/M1 成立。

新增 M0 任务必须同时写明要移除、延后或缩小的内容。不能只增加范围。

## 7. 人工试玩门

### Gate A — 大厅

确认：老皮、移动、接单、配置和节奏。

### Gate B — 飞行

确认：重量、重力、辅助、速度、镜头、碰撞和重试。

### Gate C — 赤砂星路线

确认：1–3 分钟内的星球进入仪式、俯冲/缓降、环境分段、资源余量、危险公平性
和关卡长度。

### Gate D — M0 闭环

确认：故事、角色、订单、飞行、落地和返航是否形成继续游玩的愿望。

每个 Gate 未通过前，不扩展下一个大内容层。
