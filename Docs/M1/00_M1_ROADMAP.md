# M1 Roadmap — Four-Planet Demo

## 1. 里程碑定义

**M1：Four-Planet Demo** 是第一版可对外分享的完整 Demo。它建立在已经通过人工验收的 M0 Playable Spine 上，不重新证明“大厅—驾驶舱—飞行—落地—返航”是否能连通，而是证明这套结构可以承载多颗真正不同的星球、角色和章节。

**状态：Planning Ready。** 文档与任务队列已建立；实现从 T-100 开始。

## 2. 产品目标

M1 应让玩家在约 2–4 小时的首次主线体验后明确感受到：

- 赤砂、白噪、穹林、群潮不是换皮关卡。
- 老皮和快递站持续连接每次旅途。
- 一件货物可以把自然环境、文明制度、角色目标和飞行限制连在一起。
- 玩家完成订单后，星球与站点会发生可见变化。
- 支线提供角色、升级与秘密，而不是重复刷钱。
- 武装或和平配置会被角色记住。
- 中继网确实早于银河外卖公司，但更深真相仍未揭晓。

## 3. 主线结构

```text
序章与赤砂星首单（M0 已完成）
│
├─ 第一幕：白噪星
│  ├─ 获得特高压电屏蔽罩
│  ├─ 接触记忆档案文明
│  └─ 得到中继网历史记录
│
├─ 中场：赤砂星回访与成长
│  ├─ 看到冷却系统带来的变化
│  ├─ 完成支线与低空投放
│  └─ 建立升级、关系、许可与图鉴闭环
│
├─ 第二幕：穹林星
│  ├─ 处理会吸引生物的剧情货物
│  ├─ 面对生态边界与运输需求
│  └─ 武装/和平配置产生实际反馈
│
└─ 第三幕：群潮星
   ├─ 穿越横风、潮汐、移动平台与天气塔
   ├─ 多颗星球的线索与角色立场交汇
   ├─ 明确证明中继网不是公司建造
   └─ 进入 Demo 悬念结尾与继续探索状态
```

## 4. 内容预算

### 4.1 主线与支线

- 主线/章节订单：目标 5 份。
  - 赤砂星首单：M0 已完成。
  - 白噪星主线。
  - 赤砂星回访章节。
  - 穹林星主线。
  - 群潮星高潮订单。
- 支线订单：目标 4–6 份。
  - 至少一份加急订单。
  - 至少一份正式低空投放订单。
  - 每颗新增星球至少一项可选角色或探索内容。
- 一次只携带一份订单。

### 4.2 星球最低包

每颗新增主线星球至少包含：

- 一条完整进入/配送路线。
- 一件专属剧情货物。
- 一个独特飞行机制。
- 一至两名核心 NPC。
- 一个到达场景或小型可步行区域。
- 一个纪念品或图鉴条目。
- 一个未来回访变化种子。
- 一套独立色板、背景层、环境声和主题动机。

### 4.3 成长

M1 最低形成：

- 一种主要货币：公司信用点。
- 飞船模块库存、购买和剧情模块解锁。
- 星球关系或通行许可。
- 图鉴与纪念品墙。
- 快递站至少三次可见变化。
- 至少一个模块影响主线资格。
- 至少一个配置影响角色态度或路线便利。

## 5. 开发阶段

### 阶段 G：共享系统与 M0 基线保护

目标：在制作白噪星前完成 schema v2、多星球导航、路线合同、关系/许可/图鉴、升级、支线和投放基础。

成功条件：M0 完整闭环仍通过，空白 M1 数据可以加载，M0 存档可安全迁移。

### 阶段 H：白噪星垂直切片

目标：完成第一颗新增星球的完整订单循环，验证现有架构能支持强重力、电磁暴雪、屏蔽模块和全新文明。

Gate E 判断白噪星是否真正不像赤砂星换皮。

### 阶段 I：成长、支线、投放与赤砂回访

目标：建立 M1 的长期动力，证明世界变化和可选内容比刷取更重要。

Gate F 判断升级、回访和支线是否形成自然中场。

### 阶段 J：穹林星

目标：完成树冠空间、生态压力和武装/和平反馈。

Gate G 判断生物压力是否保持非战斗，以及文明态度是否可见。

### 阶段 K：群潮星

目标：完成天气塔、海洋路线、高潮故事和中继网第一层揭示。

Gate H 判断高潮与 Demo 结尾是否足够有回报。

### 阶段 L：整合与发布候选

目标：完整串联四星、支线、回访、升级、存档、UI、音频、美术和本地构建。

Gate I 是 2–4 小时的 M1 最终验收。

## 6. 内容生产顺序

每颗星球遵循：

```text
Planet Packet
→ Order Packet
→ Character Packet
→ Resource 数据与本地化
→ 路线灰盒
→ 独特危险/机制
→ 驾驶舱与到达剧情
→ 结算、关系、许可和回访种子
→ 视听占位
→ 自动回归
→ Human Check
```

不得在 Planet Packet 未完成时投入高成本最终资产。

## 7. M0 回归保护

以下任何改动都必须运行 M0 完整回归：

- `GameState`、SaveService 或 schema。
- SceneRouter 和阶段切换。
- 对话 UI、模态协调和交互组件。
- 飞船控制、资源、伤害、HUD、检查点或交付接口。
- 数据注册表与本地化。
- 快递站、驾驶舱或共用到达场景。

M1 不以重写 M0 为前提。共享组件应通过增量接口扩展；若必须改变 M0 行为，应建立明确任务、回归和人工判断。

## 8. 范围保护

M1 不实现：

- 完整敌人战斗或地表枪战。
- 多飞船购买和船员管理。
- 程序生成路线或随机词条。
- 多单并行配送。
- 复杂贸易和经济模拟。
- 开放宇宙或任意星球降落。
- 全配音和最终发布级资产。
- 正式主线结局与隐藏结局。
- 平台 SDK、联机、成就和云存档。

任何新增系统必须回答：

1. 它是否让星球、角色、货物或旅途更有意义？
2. 它是否是四星差异或 Demo 主线成立所必需？
3. 能否先用更小、可逆、可测试的方式验证？
4. 它是否会制造重复劳动或内容指数膨胀？

## 9. 里程碑成功标准

M1 成功时，玩家应至少产生三种愿望：

1. 想继续了解老皮、中继网和银河外卖公司。
2. 想回访已经发生变化的星球与角色。
3. 想体验 Demo 之外更遥远、更陌生的星球。

若玩家只记得飞行参数而不记得角色，说明叙事连接不足；若只想跳过所有星球进入，说明路线与景观不足；若只想刷支线信用点，说明成长和内容设计偏离目标。
