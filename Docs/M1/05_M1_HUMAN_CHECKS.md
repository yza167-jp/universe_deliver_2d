# M1 Human Checks / Gate E–I

自动测试负责证明流程和状态没有明显工程错误；Human Check 负责判断星球差异、角色、节奏、可读性与继续游玩的愿望。

## 通用规则

- 只有 T-119、T-129、T-159、T-179、T-199 是 M1 强制 Gate。
- 到达 Gate 时任务与阶段进入 `Human Check`，主 Agent停止扩范围。
- 用户未明确通过前，后续依赖任务保持 `Blocked`。
- 返工只修复阻塞与高优先级问题；非阻塞打磨进入后续任务。
- 每个试玩包必须包含 commit、命令、起点、时长、步骤、3–5 个重点和已知限制。

## Gate E / T-119 — M1 基础与白噪资格

### 范围

- v1→v2 存档迁移。
- 多星球解锁、关系、许可、图鉴和站点状态基础。
- 赤砂星回访。
- 特高压电屏蔽罩确定获取。
- 档案终端和白噪星导航资格。

### 建议时长

20–40 分钟，包含一次 v1 继续游戏与一次回访流程。

### 人工问题

1. M0 已完成存档能否自然进入 M1，而不像重开新项目？
2. 赤砂回访是否展示了首单的后果和伊娅的持续存在？
3. 屏蔽罩获取是否像剧情成长，而不是系统发奖？
4. 档案终端和站点变化是否增加“家在成长”的感觉？
5. 白噪星门槛是否清楚、确定且不要求刷取？

### Gate E Round 1 试玩包

主流程使用隔离进度，不读取或写入正常玩家存档：

```bash
export GODOT_BIN="/Applications/Godot.app/Contents/MacOS/Godot"
"$GODOT_BIN" --path . --language zh_CN -- --m1-debug=gate_e
```

起点是 M0 首单完成后的大厅：赤砂星、伊娅、旧中继铭牌和 `100` 信用点已保留，
赤砂回访尚未接取，特高压电屏蔽罩与白噪导航尚未解锁。实际 v1 文件迁移由
测试专用路径自动验证；这个人工入口只提供等价、可重置且不污染玩家主档的体验
起点。

试玩步骤：

1. 查看首单纪念品与大厅状态，再到订单终端接取赤砂回访。
2. 在工作台确认配置，进入驾驶舱并完成旅行。
3. 飞过短服务航道，观察运行中的净水/冷却设施并完成着陆。
4. 在维修场完成伊娅与老皮的主对话，选择上传完整记录或保留本地记录；可查看
   冷却设备与记录终端后返航。
5. 查看结算中的关系、屏蔽罩、档案终端与下一步提示，再返回大厅。
6. 与老皮交谈一次并浏览档案终端，确认赤砂后果、白噪线索和旧铭牌异常边界。
7. 打开订单终端查看白噪风险；在工作台卸下、再装回特高压电屏蔽罩，确认门槛
   从“待安装”变为“资格已满足、航路待开放”。

如需单独检查驾驶舱中的白噪预览，使用：

```bash
"$GODOT_BIN" --path . --language zh_CN -- \
  --m1-debug=white_noise_catalog --show-debug-ui
```

关闭订单预览后，点击顶部调试栏的 `COCKPIT`，再激活 Navigation。这里只应显示
白噪风险、已安装屏蔽罩和“正式航路待开放”；不能接单或开始旅行。

已知限制：

- 白噪星订单、航路与环境仍是 `REGISTERED_ONLY`，本 Gate 不提供白噪飞行。
- `gate_e` 自动存档关闭；`F6` 会重置整个隔离起点，退出进程后不保留试玩进度。
- 新角色与货物显示名仍为 PROVISIONAL；本 Gate 不判断最终美术或英文完成度。

### Gate E Round 2 试玩包

**状态：** 自动检查与 11 张 640×360 可见录帧已通过；T-119 和阶段 B 为
`Human Check`。本节所在聚焦提交即为试玩基线，commit hash 与远程推送结果见
本轮最终报告。

使用隔离进度启动，不读取或写入正常玩家存档：

```bash
export GODOT_BIN="/Applications/Godot.app/Contents/MacOS/Godot"
"$GODOT_BIN" --path . --language zh_CN -- --m1-debug=gate_e
```

预计时长仍为 20–40 分钟。建议按以下顺序完整走一次：

1. 在起始大厅先看上方旧档案机柜：外壳应存在但处于未接通状态，不能打开图鉴。
2. 到订单终端接取赤砂回访，再进模块工作台。确认功能槽 A 显示真实的
   “陨石激光炮”、说明、独立的“本次订单不要求”和安装状态；尝试卸下再装回，
   出发必需配置不应受影响。
3. 进入驾驶舱，先分别查看老皮座位、广播、货舱和公司终端，再启动 Navigation。
   确认内容围绕净水/冷却设施、非标屏蔽改装、旧铭牌结构参考与未解释噪声，并
   清楚说明本次走已备案的维修服务短航线。
4. 完成三段飞行，依次确认 HUD 为“维修服务航道”“屏蔽材料与维修场观察”
   “变化后的维修场着陆”；留意所有 HUD、帮助、警告和对白是否仍有方框或乱码。
5. 在维修场完成伊娅/老皮剧情与上传选择，查看回访专属着陆、互动、结算和返站
   提示，不应再出现“首次前往边境、寻找失联目标”的首单语境。
6. 返回大厅后等待一次老皮接通档案接口剧情。剧情结束后机柜应通电并可浏览；
   关闭再继续操作不应重播。打开订单终端，在历史区分别选择 M0 首单和赤砂回访，
   确认两份独立只读详情、无重复 alias、无可用接取按钮。
7. 最后到工作台卸下再装回特高压电屏蔽罩，确认白噪资格在“已拥有未安装”与
   “资格满足但正式航路未开放”之间正确变化。需要重新开始时按 `F6` 重置隔离
   场景。

请重点判断：

1. 模块名称、订单角色与安装状态是否一眼可区分，且装卸行为符合预期？
2. “旧机柜一直存在 → 老皮接通 → 通电开放”的站点成长是否自然，激活剧情是否
   只出现一次？
3. 两份历史是否都容易找到、内容够用且明显只读，没有重复首单或编造飞行结算？
4. 赤砂回访的驾驶舱、三段短航线、抵达与结算是否明确区别于首次配送，三阶段
   原因是否说得通？
5. 全程中文是否清楚可读，没有十六进制缺字框、空白方块、乱码或 640×360
   严重遮挡？

已知限制：

- 白噪星订单、正式航路和环境仍为 `REGISTERED_ONLY`；本 Gate 不提供白噪飞行。
- 回访短航线继续复用 M0 后半段灰盒资产，不是第二条八阶段路线，也不恢复 Gate C
  的完整危险组合。
- schema v2 没有保存历史飞行逐项结算，因此历史明确显示“详细飞行结算未保留”；
  本轮没有扩展存档 schema 或建立第二份历史数据库。
- 档案终端、人物和路线美术仍是 M1 灰盒；本轮判断信息关系、变化感与可读性，
  不判断最终像素美术或英文完成度。
- `gate_e` 自动存档关闭；`F6` 重置隔离快照，退出后不保留这次试玩进度。

### Gate E Round 2 人工反馈

**结果：** `Rework required`。

1. 阶段 8 低空拉起时，canonical AGL 仍为有效 `PROFILE`，RayCast 与剖面也
   一致，但调试不变量把窗口内先降后升、首尾接近的正常平滑响应误报为高度冻结。
2. 赤砂回访抵达对白点击记录选择时，选项按钮仍处于 `pressed` 信号发射过程，
   UI 同步释放该按钮导致 Godot 报告锁定对象不能释放，并可能中断下一行刷新。

本轮只修复以上两个 Gate E 阻塞，不重新设计已经通过的模块、档案、历史、
回访短航线或中文字体，也不开始 T-120。

完整流程预计仍为 20–40 分钟；如 Round 2 其余项目已确认，可聚焦以下

连贯，以及完整回访闭环是否没有新回归。自动测试只能确认数值、状态和无错误
实例化，不能代替这些 Gate E 判断。

## Gate I / T-199 — Four-Planet Demo 最终验收

### 范围

从新游戏或 M0 v1 档开始，完整经历：

```text
赤砂首单
→ 赤砂回访
→ 白噪主线与支线
→ 穹林主线与低空投放支线
→ 群潮主线与加急支线
→ 中继观测室结尾
→ 退出与继续游戏
```

赤砂 Stretch 支线如果已经完成则纳入；若 Deferred 不影响 Gate。

### 建议时长

2–4 小时，可分段试玩，但最终至少完成一次连续章节状态验证。

### 最终问题

1. 四颗星球是否像不同地点、文明与旅途记忆？
2. 老皮和核心 NPC 是否让玩家愿意继续了解？
3. 主线、支线、回访、模块和站点成长是否彼此连接？
4. 飞行与交付机制是否有变化，但仍像同一款游戏？
5. 失败、重试、资源和主线门槛是否公平？
6. 2–4 小时内容是否密度合理，没有刷取和空白拖时？
7. 群潮高潮和星图外坐标是否构成有效 Demo 结尾？
8. macOS 构建、Windows 启动验证、存档、继续、可访问性和性能是否可接受？

### 完成后

- M1 所有必做阶段 Done。
- T-141 可 Done 或 Deferred。
- 创建 M1 里程碑提交/标签。
- 更新 README 与发布说明。
- 未经新的 M2 规划，不直接扩展完整游戏范围。
