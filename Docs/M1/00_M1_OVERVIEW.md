# M1 — Four-Planet Demo Overview

## 1. 状态

- M0：Done，冻结为回归基线。
- M1：规划完成，实施从 T-101 开始。
- 对外定位：第一份可分享 Demo。
- 首次主线体验目标：约 2–4 小时。
- 中文内容完整；英文保留稳定 Key 与占位列。
- 首要平台 macOS；M1 收尾验证 Windows 导出启动。

## 2. 核心证明题

M1 不只是增加内容数量，而要回答：

1. M0 的架构能否支撑四颗真正不同的星球？
2. 主线、支线、回访、模块、关系和站点变化能否形成连续旅程？
3. 飞行机制是否能由当地自然、文明与货物共同解释？
4. 玩家方式是否会被记住，同时保持主线可控？
5. Demo 是否能在不解释终极秘密的前提下形成高潮和悬念？

## 3. 主线结构

```text
M0 赤砂星首单
→ 赤砂星短回访：取得特高压电屏蔽罩
→ 白噪星：记忆档案文明
→ 穹林星：生态文明与武装封存
→ 群潮星：天气塔控制权与中继揭示
→ 快递站中继观测室结尾
```

## 4. 内容预算

### 主线

- 已完成赤砂星首单：1。
- 赤砂星回访主线：1。
- 白噪星主线：1。
- 穹林星主线：1。
- 群潮星主线：1。
- 合计：5 份主线订单。

### 支线

必做：

1. 白噪星：被退回的记忆盒。
2. 穹林星：孢子季急投，验证低空投放。
3. 群潮星：风眼前的灯，验证加急减报酬。

Stretch：

4. 赤砂星：配额之外的滤芯。预算不足时可 Deferred，不阻塞任何 Gate。

### 回访与站点变化

- 赤砂星至少一次明确回访。
- 白噪、穹林和群潮都保留未来回访种子。
- 快递站至少三次可见变化：档案终端、生态角、中继观测室。

## 5. 新增正式系统

- Save schema v2 与 v1 迁移。
- 多星球章节、解锁、关系、许可、图鉴、纪念品和回访状态。
- 主线/支线订单状态，仍一次一单。
- 加急支线与超时减报酬。
- 第二种正式交付：固定宽容接收区的低空投放。
- 三个剧情模块：特高压电屏蔽罩、生物信号隔离舱、横风稳定器。
- 武装/和平与局部选择反馈。

## 6. 明确不做

- 完整敌人战斗。
- 多飞船购买。
- 程序生成路线。
- 多单同时配送。
- 复杂贸易与维修债务。
- 开放宇宙和任意星球降落。
- Steam SDK、云存档和成就。
- 最终商业美术、完整配音和完整英文翻译。

## 7. 制作顺序

1. v2 存档与多星球基础。
2. 赤砂回访与白噪资格。
3. 白噪完整订单。
4. 支线/关系/成长共用系统。
5. 穹林完整订单与低空投放。
6. 群潮完整订单与高潮。
7. 四星整合、导出和最终 Gate。

## 8. 强制 Human Check

- Gate F / T-129：白噪完整订单。
- Gate G / T-159：穹林与低空投放。

## 9. 内容候选规则

用户选择“混合方式”：

- 稳定角色、订单、货物与场景 ID 先锁定。
- 显示名、物种细节和部分剧情标题提供 2–3 个候选。
- 文档可标注推荐工作候选，但状态保持 `PROVISIONAL`。
- 只有用户明确确认后，才在 Narrative Bible 中升级为 `LOCKED`。
