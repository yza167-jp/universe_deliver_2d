# 01 — Narrative Bible / 叙事圣经

本文件区分“已锁定正史”“暂定骨架”和“开放问题”。Codex 不得把暂定内容擅自升级为正史。

## Canon Status

- **LOCKED**：用户已确认。实现和文本不能自行改写。
- **PROVISIONAL**：当前可用于 M0/M1 的工作设定，后续可重写。
- **OPEN**：尚未决定，开发时只保留接口或最小占位。

---

## 1. 已锁定设定（LOCKED）

### 标题

- 中文：**《我在宇宙送快递》**
- 英文工作名：**Universe Deliver**

### 玩家

- 玩家是来自地球的人类。
- 玩家受雇于“银河外卖公司”，被分配到一个边境快递站点。
- 玩家不是无人格摄像机：可通过少量对话选项表达态度，但不进行大段自说自话。
- 玩家默认无配音。
- 玩家可输入名字；M0 外貌使用固定/轻量可选的制服像素形象。

### 老皮

- 老皮是一名外星人，物种外观是一只水豚。
- 他会直立行走、会说话、具有人格与职业身份。
- 不同文明通过普及的同声传译器交流，因此所有角色可以自然对话。
- 老皮是玩家固定伙伴，从游戏开始就出现。
- 老皮在前期承担新手教程，但他的功能远不止教程。
- 老皮会出现在快递站与飞船副驾驶位置。
- 名字固定为“老皮”，不由玩家命名。

### 游戏结构

- 有明确主线和结局的单人游戏。
- 主线星球按大致固定顺序解锁。
- 可以存在支线星球与回访内容。
- 主线尽量不产生大规模分叉。
- 主线结束后允许继续游玩和收集。
- 约 95% 图鉴完成度可以触发隐藏结局。

### 战斗边界

- 玩家可以走和平快递员或武装运输者倾向。
- M0/M1 第一版只实现飞船激光炮轰击陨石。
- 进入星球后的角色剧情与地表段没有战斗环节。
- 武装选择可以影响 NPC 态度、检查和对白。

### 基地与飞船

- 快递站大厅是 2D 俯视可步行空间。
- 初始主要员工只有玩家和老皮。
- 玩家长期使用一艘飞船，而不是频繁换船。
- 飞船通过数值升级、模块升级与剧情功能升级成长。
- 快递站可以升级并产生可见场景变化。
- 中后期站点可能迁移、受损或被迫离开，但尚未锁定。

### 交付与人物

- 落地后的主要表现采用“场景式对话 + 小型可步行区域”。
- 普通订单可以只使用场景式对话。
- 重要主线地点可开放 1–2 屏的小区域与 NPC/物件互动。
- 交付方式随剧情变化，包括着陆、空投、检查门和对接等。

## 2. 暂定世界骨架（PROVISIONAL）

### 银河外卖公司

工作名：**银河外卖公司**。英文法人名暂未锁定，可在 M0 UI 中使用 `Galactic Delivery Corporation` 作为占位。

公司不是简单的纯恶反派。目标是“荒谬、庞大、官僚、逐利，但内部也有普通人和必要服务”。

公司特征：

- 将跨文明配送包装成生活服务与文明连接工程。
- 对所有风险拥有冗长免责条款。
- 管理层会在货物受损时来电，语气礼貌但冷酷。
- 依赖一套远早于公司成立的物流基础设施，却在宣传中暗示全部由公司发明。
- 对边境站点采取成本中心思维，因此玩家站点面临关闭或合并压力。
- 公司并非所有事件的唯一幕后黑手；某些部门、员工和客户可能真诚帮助玩家。

写作禁忌：

- 不把公司写成每句台词都在大喊“我们很邪恶”。
- 黑色幽默必须同时传递有效信息。
- 不让公司制度压倒所有星球自身冲突。

### 同声传译器

- 常见基础设施，让不同物种交流无需反复解释。
- 翻译通常自然，但可在少量情节中出现文化语义偏差。
- 不将“语言不通”作为每颗星球的重复障碍。
- 传译器可能与古老物流网络共享某些协议，这是潜在伏笔，不是 M0 必须揭示的事实。

### 古老物流网络

暂定名称：**中继网 / Relay Lattice**。

当前故事骨架：

> 玩家被派到一座即将被关闭的边境快递站。某天，公司系统生成一份无法取消、无法追溯发件部门的订单，收件地址位于公司星图中“不存在”的坐标。为了获得航行权限和必要模块，玩家与老皮依次前往不同星球，完成当地订单并重新激活一批被公司当作普通物流节点使用的古老设施。玩家逐渐发现，这套网络不是公司建造的，而水豚物种或老皮本人似乎能听见网络中的某种信号。

该骨架可用于 M1 铺垫，但以下内容仍开放：

- 网络由谁建造。
- 网络真正运输的是物质、信息、生命、记忆还是别的东西。
- 老皮与网络是物种关联、个人经历还是巧合。
- “不存在的收件地址”是否位于银河之外。
- 公司高层知情程度。

### 结局方向

普通结局暂定围绕：

- 将网络控制权交给公司。
- 让各星球共同管理或公开网络。
- 关闭/破坏关键部分以阻止滥用。

隐藏结局暂定：在图鉴约 95% 后发现网络连接范围远超当前银河，并解锁新的最终选择或目的地。

M0 不实现结局系统，只写入可扩展的剧情标记。

## 3. M0 故事概要（PROVISIONAL）

### 序章：边境站点

玩家抵达/开始工作时，站点已经长期缺员。老皮熟悉设施和公司流程，用看似随意的方式带玩家完成入职。

公司通知：

- 站点处于“运营效能观察期”。
- 若未达成最低配送指标，将被自动合并。
- 合并说明中对老皮的员工安置条款含糊不清。

第一单表面上是一份常规赤砂星工业货物，实际收件人与公司档案存在轻微矛盾。

### 第一份货物（工作设定）

工作名：**深层冷却泵核心**。

公司描述：

> 用于赤砂星 7 号采掘区生产维护的标准冷却设备。

客户历史显示：

- 收件账户近期连续下过多份冷却与净水设备订单。
- 其中若干订单被公司以“工业配额异常”取消。
- 实际收件地点并非公司正式仓库，而靠近工人居住区。

玩法关系：

- 货物对强烈碰撞敏感，完整度影响当地设备能否立刻启用。
- 货物并不限制所有 Boost，但进入中层雷暴后 Boost 会提高损伤风险。
- 货物信号会使公司设施更容易识别玩家，因此峡谷低飞具有叙事理由。

### 赤砂星抵达

玩家选择：

- 快速俯冲：老皮更紧张，抵达更快；当地 NPC 对驾驶风格有反应。
- 缓慢滑翔：触发额外景观/广播信息；公司扫描暴露时间更长。
- 常规进入：中性反馈。

玩家穿过殖民公司雷达，最终在居民维修场着陆。

### 第一位星球 NPC（工作设定）

工作名：**伊娅 / Iya**。

- 赤砂星当地技术员，负责维护聚居地冷却和净水系统。
- 不把自己描述为英雄，只想让设备运行到下一个风季。
- 对银河外卖公司既依赖又不信任。
- 知道货物订单记录被改写，但不知道是谁改写。
- 给予玩家一件旧中继节点碎片/铭牌作为纪念物或线索。

M0 结尾：

- 玩家返回站点，获得信用点和一次站点变化。
- 老皮对中继碎片产生一瞬间异常反应，但没有完整解释。
- 导航系统短暂显示三个新的远方星球轮廓，为 M1 留下钩子。

## 4. 四颗主线星球框架（PROVISIONAL）

### 4.1 赤砂星 / Red Sand

**自然：** 沙漠、深峡谷、尘暴、遗迹、低水资源。

**文明：** 公司采掘殖民区、工人聚居地、旧本地设施。

**冲突：** 资源控制、生产配额与居民生存需求。

**飞行：** 雷达迫使低飞穿峡谷；陨石和大气雷暴作为第一套完整危险。

**故事功能：** 教程星球；第一次暴露公司档案与现实不一致；发现中继网线索。

**回访种子：** 冷却系统运行后，聚居地出现新空间和新的订单。

### 4.2 白噪星 / White Noise

**自然：** 冰原、冰洞、极光、电磁暴雪、较强重力。

**文明：** 居住于冰层下、以保存记忆与档案为核心的文明。

**冲突：** 哪些记忆应该保存、删除或公开；公司将其档案服务商品化。

**飞行：** 低能见度、电磁干扰和高压环境；需要特高压电屏蔽罩。

**故事功能：** 第一次要求玩家通过确定的支线/剧情获得特定模块；揭示中继网历史记录。

**回访种子：** 玩家选择影响一部分档案是否对外开放。

### 4.3 穹林星 / Canopy World

**自然：** 巨树、树冠城市、藤蔓、孢子云、飞行生物。

**文明：** 强调生态互依、对外来武器高度警惕的树冠文明。

**冲突：** 外部运输需求与生态边界；某件货物会吸引当地生物。

**飞行：** 穿越树洞与树冠通道；货物气味/信号吸引生物，但 M1 不必进入战斗。

**故事功能：** 明确反馈玩家是否安装武器，推进和平/武装身份差异。

**回访种子：** 某条生物迁徙路线因玩家交付而变化。

### 4.4 群潮星 / Tidal Archipelago

**自然：** 海洋、岛屿群、强风、雷暴、巨大潮汐。

**文明：** 多个相互竞争的岛屿城邦与天气塔网络。

**冲突：** 谁控制天气和航路；公共安全与城邦权力。

**飞行：** 海面低飞、横风、雷暴、移动平台与天气塔。

**故事功能：** M1 高潮；多个早期角色/线索交汇；首次清晰证明中继网不是公司建造。

**回访种子：** 天气塔状态改变后开放新的岛屿和深海信号。

主线推荐顺序：赤砂 → 白噪 → 穹林 → 群潮。

## 5. 角色写作规则

### 老皮的声音

老皮应当：

- 经验丰富，但不是无所不知。
- 说话直接、松弛，偶尔把危险当成行业常识。
- 能在荒谬公司流程中找到实际可行的办法。
- 会关心玩家，但不总用煽情方式表达。
- 对吃、休息、温度和水有水豚式偏好，但不能只靠动物梗存在。
- 在教程里解释“做什么”，很少解释“按哪个键”；具体按键由 UI 提示。
- 偶尔沉默，让环境和玩家行动说话。

避免：

- 每句都抖包袱。
- 把他写成幼儿化宠物。
- 让他替玩家完成所有推理。
- 过早明确他与终极秘密的关系。

### 玩家对话

玩家选项通常为态度差异，而非彻底改变主线：

- 真诚/关心。
- 职业/务实。
- 怀疑/讽刺。

选项数量常规为 2–3。避免大量只有措辞不同、无任何反馈的假选择。

### 星球 NPC

每个主要 NPC 至少具备：

- 一个当前具体目标。
- 一个与当地文明有关的日常细节。
- 一个对公司或配送网络的独立立场。
- 一处与玩家初始印象不完全一致的特征。
- 一个回访时可变化的状态。

NPC 不应只承担百科说明或发奖功能。

### 公司管理层

公司警告的写法：

1. 先给出具体可操作信息。
2. 再用制度化措辞制造黑色幽默。
3. 不连续打断玩家。
4. 避免在高难操作时播放长对白。

示例语气，不是最终文本：

> 检测到货物完整度下降。依据《跨星系易损件友善关怀准则》，本次事故将被记录为您主动参与的职业成长活动。

## 6. 货物叙事模板

每件主线货物至少定义：

```text
cargo_id
name_key
sender_character_id
recipient_character_id
origin_planet_id
destination_planet_id
company_description_key
story_description_key
hidden_description_key (optional)
customer_history_keys[]
flight_restrictions
delivery_method
required_modules[]
recommended_modules[]
failure_consequences
associated_story_flags[]
```

公司描述、实际用途和隐藏信息不必一致，但差异必须服务故事，不是每单都用“公司撒谎”重复同一反转。

---

## 7. 分支与回访规则

- 主线星球顺序固定或仅有极少局部交换。
- 选择主要改变：NPC 关系、后续对白、当地视觉状态、支线开放、结局变量。
- 重要星球至少计划两次访问：初识与回访。
- 回访必须展示变化，不只是复用同一对话。
- 不为 M0 实现多结局；只建立稳定剧情标记。
- 隐藏结局条件不要要求绝对 100%，目标约 95%，避免单个错过内容永久锁死。

## 8. 开放问题（OPEN）

这些问题不阻塞 M0：

- 玩家姓名、外貌选项的最终范围。
- 银河外卖公司的正式英文名、品牌色和组织结构。
- 老皮的具体年龄、过去和加入公司的原因。
- 老皮是否知道中继网真相，知道多少。
- 水豚物种的母星与文化。
- 快递站中后期是否迁移、受损或被迫离开。
- 古老物流网络的创造者和真实用途。
- 普通结局的确切数量与内容。
- 隐藏结局是否进入银河外区域。
- 赤砂星 NPC 的最终姓名与文化语言细节。

实现涉及这些内容时，使用可替换 ID 和占位文本，不要自行永久锁定。
