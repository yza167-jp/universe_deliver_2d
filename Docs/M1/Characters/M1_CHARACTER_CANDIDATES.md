# M1 Character Candidates / M1 角色候选

用户选择“混合方式”：稳定角色 ID 和叙事职责先确定，显示名、物种与部分细节提供 2–3 个候选。用户明确选择前全部保持 `PROVISIONAL`。

## 使用规则

- 代码、Resource、存档和条件使用 Stable ID。
- 本地化表可暂用“职务称呼”或推荐工作候选。
- 不得根据 Agent 偏好创造第四个名字并静默替换。
- 用户确认后，在 Narrative Bible 中标记选中项为 `LOCKED`，其余候选保留为 rejected/unused 记录。

## 1. White Noise Archivist

```text
character_id: character_white_noise_archivist
role: 白噪星核心 NPC / 档案维护者
canon_status: PROVISIONAL
```

### 角色职责

- 具体目标：恢复失效索引，同时阻止未经授权的商业批量访问。
- 日常细节：长期在低温档案层工作，会随手记录设备声响和霜纹变化。
- 公司立场：承认公司运输不可替代，但不信任公司对“访问权”的定义。
- 初印象 vs 深层：初见冷静克制，实际非常在意被档案制度忽略的普通生活。

### 名字候选

1. **推荐工作候选：弥珥 / Mier**
   - 简短、安静，适合克制的档案维护者。
2. 缇芮 / Tiri
   - 更轻、更年轻，适合强调个人记忆故事。
3. 瑟莱 / Serai
   - 稍正式，适合制度内资深维护者。

### 物种候选

A. 半透明角质皮肤的低温两栖类，体内有可见热纹。  
B. 覆有短绒与冰晶角片的矮壮类人生物。  
C. 细长四臂档案族，额外双臂主要用于精细维护。

**推荐：A**，与冰下光带和记忆可视化最统一，但未锁定。

### 说话方式

- 句子短、精确。
- 很少使用绝对词。
- 幽默来自档案制度与人的不可分类性。
- 不把记忆问题说成抽象哲学讲座。

## 3. Canopy Route Keeper

```text
character_id: character_canopy_route_keeper
role: 穹林星核心 NPC / 树冠航路协调者
canon_status: PROVISIONAL
```

### 角色职责

- 具体目标：在迁徙季维持核心树冠航道与幼林隔离。
- 日常细节：用风、孢子密度和生物叫声判断路线，而不是只看仪表。
- 公司立场：认为外部物流有用，但反对公司把生态窗口当成可随时购买的时隙。
- 初印象 vs 深层：初见对武器非常强硬，之后会承认自己也依赖外来医疗和设备。

### 名字候选

1. **推荐工作候选：苔音 / Taiyin**
2. 弦枝 / Xianzhi
3. 诺芥 / Nojai

### 物种候选

A. 与树冠共生、具有叶片状耳/鳍的轻体型类人。  
B. 六肢攀援物种，站立时使用后四肢，前肢负责工具与手势。  
C. 由多种菌丝共生形成的个体，外观仍保持清楚角色轮廓。

**推荐：A**，动画与像素轮廓成本最低；C 可保留为未来角色。

### 说话方式

- 使用航道、季节和生态关系的具体词。
- 不用“自然是神圣的”一类空泛台词。
- 对武器说法直接，但允许玩家解释。

## 5. Tidal Weather Keeper

```text
character_id: character_tidal_weather_keeper
role: 群潮星核心 NPC / 天气塔维护者
canon_status: PROVISIONAL
```

### 角色职责

- 具体目标：在塔网故障扩大前恢复民用航路和安全窗口。
- 日常细节：习惯按风向安排睡眠，衣服和工具永远带防盐层。
- 公司立场：需要公司的零件和运输，但反对远程托管者不理解岛链维护成本。
- 初印象 vs 深层：看似只关心设备，实际上非常在意小岛居民是否被主航路遗忘。

### 名字候选

1. **推荐工作候选：娜茵 / Nayin**
2. 阿穆 / Amu
3. 澜德 / Lande

### 物种候选

A. 有短鳃褶、耐盐皮肤的两栖类人。  
B. 轻型甲壳物种，外壳用于抵御风沙盐雾。  
C. 带羽膜的海岛滑翔物种，但不会在游戏中自由飞行。

**推荐：A**，与天气塔维护和海洋生活最直观。

### 说话方式

- 用非常具体的风向、窗口和设备词。
- 不崇拜天气，也不把塔网描写成纯技术奇迹。
- 黑色幽默来自“安全窗口必须先经过预算批准”。

## 7. 公司远程角色

M1 暂不增加必须现场建模的公司管理层角色。使用稳定 ID：

```text
character_company_dispatch
character_company_archive_service
character_company_weather_custodian
```

它们可以是部门/终端身份，不必立即具名。若需要固定个人角色，应另行向用户确认。
