# M1 Four-Planet Demo — 路线图

## 状态

**Planning complete / Implementation not started**。

M0 已完成并冻结为回归基线。M1 的任务计划、产品边界、技术增量和第一颗新增星球的内容包已经建立；合并本规划后，主 Agent 从根目录 `DEVELOPMENT_TASKS.md` 中最早的 `Ready` 任务开始实施。

## M1 要证明什么

M1 不是“在赤砂星模板上换三套背景”，而是要证明：

1. 四颗星球能同时在自然、文明、人物、货物与飞行机制上形成差异。
2. 玩家愿意沿基本线性的主线继续认识角色和追查中继网。
3. 飞船、快递站、关系、许可、图鉴和支线形成轻量成长，而不是刷取劳动。
4. 已完成星球会发生变化，回访具有叙事价值。
5. M0 的飞行、存档、模态 UI 和完整闭环不会因内容扩展而失稳。

## 目标体验

```text
M0 序章与赤砂星首单
→ 白噪星：较强重力、电磁暴雪、记忆档案文明
→ 赤砂星回访：看到首单带来的变化，建立成长与支线循环
→ 穹林星：树冠飞行、生态边界、和平/武装态度反馈
→ 多星球支线、许可、升级与回访收束
→ 群潮星：横风、海面、天气塔、Demo 高潮
→ 中继网第一层明确揭示
→ 悬念结尾并保留继续游玩
```

## 产品级完成标准

M1 完成时至少满足：

- 四颗主线星球可进入：赤砂、白噪、穹林、群潮。
- 4–6 份主线订单，星球顺序大体固定。
- 每颗星球至少 1–2 名核心 NPC 和一个可回访变化种子。
- 至少一颗星球完成明显二次访问；当前计划为赤砂星。
- 至少一种新的正式交付方式：低空投放。
- 少量支线订单，包含一份加急订单和超时减报酬。
- 飞船模块、快递站状态、星球关系/许可和图鉴形成初步循环。
- 武装/和平倾向至少在穹林星产生可见角色与通行反馈。
- 群潮星结尾明确证明中继网并非银河外卖公司建造。
- 首次主线体验约 2–4 小时；支线和回访不靠重复刷取延长时长。
- M0 存档可安全迁移，M0 完整闭环继续通过回归。

## 实施顺序

### 1. 先建立 M1 基础，不直接制作白噪星关卡

必须先完成：

- M0 存档到 schema v2 的迁移。
- 多星球解锁、关系/许可、图鉴、回访和支线订单数据。
- 多目的地导航和主线推进。
- 从赤砂星实现中抽出可复用的路线与内容模板。
- 星球内容测试模板。

### 2. 以白噪星验证“第二颗星球不是换皮”

白噪星是 M1 的第一个垂直切片。只有 Gate E 通过后，才批量进入穹林星与群潮星的高成本内容生产。

### 3. 在第三颗星球前建立成长和回访

白噪星之后先完成赤砂星回访、低空投放、支线和站点/飞船成长，证明已有内容会变化且新系统不依赖刷取。

### 4. 穹林星验证和平/武装差异

不增加完整战斗。武器状态改变信任、检查、路线便利或对话；生态压力使用移动障碍与路线变化表达。

### 5. 群潮星承担 Demo 高潮

群潮星必须回收前面星球的角色、许可、模块和中继网线索，不只是第四个并列订单。

## M1 非目标

- 完整敌人战斗、海盗战斗或地表枪战。
- 多飞船购买和船员管理。
- 程序生成星球或路线。
- 多单同时配送。
- 复杂贸易、贷款、维修债务或动态价格。
- 完整空间站建设模拟。
- 完整主线结局和 95% 图鉴隐藏结局。
- 为了 M1 一次性重写 M0 飞行或对话架构。
- 在内容包未批准前制作高成本最终资产。

## 里程碑保护规则

- 每颗新增星球先完成 Planet Packet、Order Packet 和 Character Packet。
- 每颗星球先灰盒节奏、危险和交付，再制作专属美术。
- 共用系统可以抽取，星球自然、人文、冲突、角色与独特机制必须定制。
- M0 回归失败时，当前 M1 任务不得标记 `Done`。
- 到达 Gate 后停止扩展，优先处理用户真实试玩反馈。
- 新系统必须明确属于 M1 必要、M1 打磨或远期；远期内容不进入当前任务。
