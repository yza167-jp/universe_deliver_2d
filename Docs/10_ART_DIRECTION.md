# 10 — Art Direction / 美术方向

## 1. 视觉一句话

**较高分辨率像素画中的复古未来主义：巨大的宇宙与星球包围渺小的快递员，工业企业界面带着旧时代乐观主义的外壳，角色与生活空间却始终温暖。**

关键词：

- Retro-futurism / 复古未来主义
- Quiet solitude / 孤独宁静
- Warm companionship / 温暖陪伴
- Monumental planets / 巨型天体
- Corporate absurdity / 企业荒诞
- Readable danger / 可读危险

## 2. 技术画布

- 内部分辨率：640×360。
- 画面比例：16:9。
- 1280×720 等精确倍数窗口自然保持整数比例；真全屏允许 fractional fit，以最大 16:9 区域显示。
- 纹理 nearest filtering。
- 不裁切、不拉伸变形；真全屏的少量非整数像素尺寸差异优先于大面积可避免黑边。
- UI 与游戏世界采用一致像素密度，但 UI 字体可略细致以保证中文可读。

这是“较高分辨率像素风”，不是 160×90 的极低分辨率复古复刻。允许更细的环境层次、人物表情和仪表信息。

## 3. 形状语言

### 快递站与公司

- 圆角矩形终端、厚边框、模块化工业面板。
- 老旧塑料、搪瓷标识、贴纸、维修补丁。
- 企业品牌喜欢“可靠、亲切、跨文明服务”的乐观图形。
- 实际设备存在磨损、异响和临时修补。
- 公司 UI 规整、对称；玩家生活区更不规则、更温暖。

### 玩家飞船

- 清晰侧面轮廓，船头、驾驶舱、货舱和引擎一眼可辨。
- 不是战斗机主导轮廓，更像被长期改装的工业快递船。
- 模块升级应在外观上有小而明确的变化：炮口、屏蔽罩节点、稳定翼、传感器。
- 高速时仍能从背景分离。

### 老皮

- 必须保留水豚的宽头、短耳、厚躯干和沉稳轮廓。
- 直立行走，但不能变成普通人身体上贴水豚头。
- 制服/工具带体现职业身份。
- 表情克制，更多依靠眼睛、耳朵、姿态和停顿。
- 副驾驶姿态应有“已经很习惯危险”的松弛感。

### 文明建筑

每颗星球的建筑必须同时回答：

- 如何适应当地环境？
- 谁建造、维护和使用？
- 当地如何运输货物与人员？
- 公司设施如何侵入或适应当地风格？

## 4. 像素密度与尺寸

工作基准：

| 类型 | 建议尺寸 |
|---|---:|
| 大厅玩家 | 32×48 / 32×64 |
| 老皮大厅 | 40–48×48–64 |
| 飞船侧视 | 96–128×40–64 |
| 小型 NPC | 与玩家同密度 |
| 头像 | 96×96 或 128×128 |
| 半身立绘 | 192–256 px 高 |
| 货物图标 | 32×32 / 48×48 |
| 模块图标 | 32×32 |
| UI 基础网格 | 8 px，主要间距 4/8/16 px |

同场景中不混用明显不同的像素密度。生成图必须经过重采样/人工修整，不能直接把“仿像素但像素大小不一”的图放进游戏。

## 5. 颜色原则

- 深色宇宙背景不使用纯黑，保留蓝紫/青绿微差。
- 温暖安全区使用琥珀、橙、柔和青绿。
- 公司 UI 使用干净但略陈旧的高识别色。
- 危险红只用于即时风险，不作为所有装饰色。
- 星球通过主色与强调色区分，但地形碰撞轮廓始终清楚。
- 高对比度辅助模式使用明度、轮廓与图案，不只换色。

## 6. 快递站大厅

### 氛围

- 像一个被公司遗忘但仍有人生活的偏远办公室/车库。
- 大空间中的少量暖灯，窗外或舷窗是深色宇宙。
- 有植物、杯子、工具、毛巾、零食和老皮休息痕迹。
- 订单终端比其他设备更亮、更规整，体现公司控制入口。

### 初始构图

关键区域：

- 中央工作/通行区。
- 订单终端。
- 驾驶舱/机库门。
- 模块工作台。
- 老皮休息区。
- 纪念品墙空位。

升级后优先增添可见生活感，而不是把场景变成豪华基地。

## 7. 第一人称驾驶舱

- 画面中心/上方是窗外宇宙与巨大天体。
- 下方/两侧是可交互仪表。
- 老皮位于明显但不遮挡窗外的位置。
- 热点状态通过微光、边框或小图标提示，不使用巨大现代 App 按钮。
- 导航屏与公司终端设计语言不同：导航更实用，终端更企业化。
- 星球接近时窗外景观逐步占据画面，形成期待。

允许轻微玻璃反光和扫描线，但不能影响文本和像素边缘。

## 8. 横版飞行构图

### 背景层

建议 5–8 层，按场景调整：

1. 深空/天空底色。
2. 星点或远云。
3. 巨大星球/天体。
4. 远景地貌/城市。
5. 中景结构。
6. 可碰撞主地形。
7. 前景遮挡（少量）。
8. 粒子/天气。

可碰撞层必须比背景更高对比，避免“看不出什么能撞”。

赤砂星完整圆盘遵守单一阶段控制规则：

- 阶段 1 以较小圆盘作为远处目标，并缓慢移动。
- 阶段 2 明显增大并向主要视线区域移动；阶段 3 相对阶段 1 达到约
  `2.5–4×` 尺度，中心逐步下移，为进入大气准备。
- 阶段 3 后半段至阶段 4 前半段使用一条约 `4000 m / 12.63 s` 的连续视觉曲线；
  阶段 4 第一帧必须继承上一帧的位置、缩放、透明度与辉光，不重设圆心。
- 圆盘持续放大、圆心平滑下移，画面中的完整天体自然变成越过屏幕边缘的弧形
  地平线；Alpha 在可见弧面基本移出画面前保持不透明，禁止用快速淡出掩盖跳变。
- 曲面地平线必须与圆盘共用同一局部圆弧、锚点位置和尺度，不能换成无关的
  固定屏幕水平线；大气薄辉光、高层云、色调、入层粒子和星空衰减也消费同一
  视觉进度。阶段标签变化不得改变这条空间曲线。
- 阶段 5–8 禁止继续显示完整圆盘；雷暴、低层云、峡谷和着陆只使用天空
  渐变、地平线、远山、沙漠和设施视差建立空间参照。

该规则由背景阶段控制器统一驱动位置、缩放、透明度和可见性；检查点恢复使用
同一进度状态，不用多个独立 Tween 争抢圆盘表现，也不得用快速淡出、闪白或
重度模糊掩盖位置、尺度或曲率断层。

星系外缘、陨石带、近轨道、大气边缘和雷暴层只使用背景色带、天体、云层与
视觉危险，禁止出现暗示可接地的平直边缘。第一条高对比、可碰撞地表从低层云
之后逐步进入画面；碰撞层与可见地形必须在同一阶段启用，不能提前放置无视觉
来源的地面。阶段 5 后半可以在幕后按真实进入轨迹建立未来地表的垂直坐标，
但不能提前显露地面；阶段 6–8 的地表色带、边缘、设施、阶段标识、雷达与平台
必须共享该偏移一起进入构图，禁止只移动碰撞或只移动剖面造成视觉错位。

阶段 6 的低层沙漠设施管制区使用较密的近景结构、地面扫描束和清楚的最低安全
高度带表达“低飞危险、高飞安全”；不再以青色贴地掩护或遮挡断锁鼓励钻地形。
阶段 7 主动减少近景遮挡、拉开天空和远景，以稀疏高位航标表现无雷达的准备
走廊。阶段 8 再强化平台灯、下降指引、平台轮廓和进近方向，构图重心从高空
观察逐步转为向下对准。三段通过场景密度、天空占比和参照物变化区分，不另建
全局 UI 或战斗表现。

### 速度感

使用：

- 视差速度差。
- 引擎尾焰长度。
- 少量速度粒子。
- 星球/地形尺度变化。
- 相机 look-ahead 和轻微拉远。
- 音频动态。

推进尾迹必须是船体局部反馈：喷口子节点使用局部坐标、沿船体反方向发射且无
世界重力，抬头/低头时随船体旋转；普通推进短而稳定，松开后快速消失。Boost
在同一方向上使用更长、更亮的青色尾迹，并叠加更强速度线、发动机音高/音量和
轻度镜头前视/拉远。倒车不继续显示强烈后方主推进尾迹。

避免：

- 大面积运动模糊。
- 无法关闭的强屏幕抖动。
- 遮挡地形的密集速度线。

## 9. 四颗星球视觉方向

### 赤砂星

- 主色：铁锈红、赭黄、暗紫阴影、工业青绿灯。
- 轮廓：深峡谷、长水平地层、巨大挖掘设施、旧管线。
- 大气：高空冷暗，入大气后逐渐转橙红；雷暴为紫白闪光。
- 文明：公司设施规整巨大，居民维修区拼接、实用、有生活痕迹。

### 白噪星

- 主色：冰蓝、灰白、深海蓝、极光绿/粉。
- 轮廓：冰盖裂缝、冰下建筑、档案塔、埋在冰中的光带。
- 天气：高对比雪粒与电磁噪声，但辅助模式需保留地形边缘。
- 文明：保存与分类的视觉语言，层层档案、透明/半透明材料。

T-123 production placeholder 使用以下可执行层次：

- 轨道接近以冻结星球弧、冰盖同心层和极光薄环建立第一眼身份，不复用赤砂的
  橙红大气与沙尘地平线。
- 地表按深海蓝高空、远景冰脊、中景冰层、可碰撞冰面、少量天气粒子组织；
  可碰撞上缘使用明亮冰白，高对比模式才切换为黄色，不让背景冰层冒充碰撞。
- 裂谷使用半透明顶层、悬垂冰锥和三条稳定航标；档案区使用重复竖柱、校验光带
  与半透明库格表现“保存与分类”，不依赖大段说明文字。
- 极光绿/粉是连续宽色带，高压弧与斜向雪线是危险节奏；电磁屏幕噪声只作局部
  压力，不覆盖 HUD 或碰撞轮廓。
- 高对比辅助必须同时降低世界雪线、屏幕干扰线、雪粒 Alpha/数量和脉冲闪光，
  而不是只换航标颜色。当前程序图形属于 production placeholder，不锁定最终
  纹理、角色美术或商业配乐。

T-124 冰下目的地延续同一色彩与结构语言，但通过场景职责区分于飞行路线：

- `1.5` 屏档案站以重复库格、青色索引线、冰层顶板和深海蓝地坪组织空间；琥珀
  竖向分隔标明交付侧与保管侧，不增加大型地下城或谜题房间。
- 交付冷核、索引终端、返航升降梯分别使用青色数据光、粉色私人记录线与琥珀
  状态灯；核心 NPC 和可选角色只用职务色与灰盒轮廓区分，不据候选文档锁定物种
  外形。
- 两段相机范围内的世界标签必须完整可读；阻塞对白、非阻塞观察和顶部场景状态
  延续 M0 的信息层级。当前程序绘制是 Gate F production placeholder，不承诺
  最终纹理、角色立绘或档案设施美术。

### 穹林星

- 主色：深绿、青蓝、暖黄孢子、珊瑚色生物点缀。
- 轮廓：巨大树干、树洞、悬挂桥、树冠城市。
- 生态：背景生物缓慢移动，飞行生物不表现为传统敌人红点。
- 文明：结构像生长/编织出来，与公司金属箱形成冲突。

### 群潮星

- 主色：深海蓝、青绿、暴风灰、天气塔金色/红色信标。
- 轮廓：岛屿剪影、海面反光、塔、吊桥、移动平台。
- 天气：云墙、远闪电、雨幕和海浪层。
- 文明：多个城邦有共通技术基础但标志与建筑轮廓不同。

## 10. UI 方向

### 视觉语言

- 复古企业终端 + 航空仪表。
- 清晰的像素字体、少量图标和高可读数字。
- 边框和分隔遵循 8 px 网格。
- 动画简短：打字、扫描、灯光、机械切换。

### 信息层级

- 标题/重要危险：最大、最高对比。
- 正文/订单说明：稳定阅读宽度。
- 次要历史/帮助：可展开。
- 不把所有资源条常亮到同等强度。
- 对话、订单终端、工作台等模态打开时，场景交互提示与非必要目标条必须完全隐藏。
- 大厅目标条不超过安全宽度约 40%，最多两行，并避开中央通路、玩家、老皮和当前目标。
- 订单终端使用紧凑分类目录与单项详情两层结构；首屏优先显示订单名、目的地/风险、报酬、必需模块和接取动作，环境、货物详情与客户历史只在当前选中项的详情区滚动阅读。
- 飞行默认界面采用 Essential HUD：只突出运动、环境、重力补偿、资源与当前目标，不让完整开发遥测常驻遮挡中央飞行区域。
- Full Diagnostics 默认隐藏并可明确关闭；关闭后不保留空背景或透明输入区域。
- Gate 路线卡默认使用不超过安全区约 35%–40% 的紧凑三行结构，只显示进度、当前测试名和一行提示；完整清单按需展开，仍须避开飞船和当前测试目标。
- 公司货损警告复用路线卡占位，不额外侵占中央飞行区；用明确标题、`！/！！/！！！`
  和操作建议表达严重度，颜色只作辅助。提示先可行动、后黑色幽默，结束后恢复
  路线卡，底部即时状态可同时保留。
- 飞行帮助中的路线提示与高对比度地形必须显示文字开关状态并支持键盘焦点；
  高对比模式至少同时增强可碰撞地形轮廓的明度与宽度，不只替换色相。

### 中文字体

- 选择支持简体中文且许可证允许发布的字体。
- 字体文件属于外部资产，记录到 Attribution。
- 不在仓库中使用来源不明系统字体副本。
- 实测 640×360 下 12–18 px 等级可读性；最终字号依字体调整。

## 11. 角色立绘

- 重要对话可用头像或半身立绘。
- 不要求每句都有复杂表情切换。
- M0 老皮与赤砂 NPC 每人至少：中性、友好/放松、担忧/严肃。
- 轮廓与色块优先，细节不应在 640×360 缩小后消失。
- 背景可用地点像素插画，不另建大型步行场景。

## 12. 动画预算

M0 最低：

- 玩家：待机、行走。
- 老皮：待机、行走/转身、说话/动作姿态。
- 飞船：引擎、Boost、护盾命中、轻损伤、激光。
- 环境：星空/云/沙尘/雷暴/少量设施。
- UI：交互提示、终端加载、接单、结算。

优先用部件动画、Shader/粒子和少帧循环，避免过早制作大量逐帧动画。

## 13. VFX

- 推进与 Boost 颜色/长度明显不同。
- 擦碰火花沿碰撞点和速度方向生成。
- 护盾反馈为短时轮廓/弧面，不常驻遮挡飞船。
- 雷电预警先平滑追踪飞船，再用更强颜色/音效锁定，最后才显示短促落雷；
  高飞与低飞的预警都必须留在画面安全区，锁定后视觉不能继续黏船移动。
- 低空管制雷达的扫描应从地面设施指向最低安全高度；高位状态清楚、安静，低于
  安全线后才升级扫描色、警报、锁定和短促脉冲静电，且必须直观指向“高度过低”。
- 大气层进入通过粒子密度、光色、震动和音频共同表达。
- 激光是窄、亮、稳定的像素光柱：按住时连续、不随伤害 Tick 闪断，命中时
  截断到陨石表面，松开只允许极短淡出；不变成屏幕弹幕。
- 推进、Boost、反推、Beam 与船体碰撞火花属于飞船附着效果，必须使用船体
  局部坐标或真实船体碰撞点并随飞船移动；停止操作或重试后不得留在旧位置。
- 着陆尘埃等世界空间效果只在真实接触点一次性生成；阶段切换、失败、重试和
  离场必须清理。禁止在 CanvasLayer 或视口底部固定放置无来源的环境粒子；
  CanvasLayer 仅用于确实属于屏幕空间的闪光、色调和压力反馈。
- 所有闪光受可访问性设置控制。

## 14. 生成式美术工作方式

由助手生成首批美术时，应一次只解决一个资产包：

1. 先生成概念/方向图。
2. 选定轮廓和色板。
3. 再生成正交/可切分版本。
4. 将结果按像素网格重处理。
5. 在游戏截图中验证。
6. 记录为占位或候选。

### 示例提示结构

```text
Subject: upright alien capybara courier named Lao Pi
View: 3/4 character portrait / top-down sprite / side cockpit pose
Style: high-resolution pixel art, retro-futurist 1980s sci-fi, restrained expression
Palette: warm amber, muted teal, deep navy
Constraints: clean silhouette, no text, no watermark, consistent pixel grid,
industrial courier uniform, capybara anatomy preserved, not a human body with animal head
Background: transparent or simple flat key color
```

对场景背景需明确分层需求，不把一张完整插画直接当可碰撞关卡。

## 15. 美术验收

资产进入 `production` 前：

- [ ] 像素大小一致。
- [ ] 轮廓在游戏缩放下可读。
- [ ] 无伪文字、水印、畸形结构。
- [ ] 与当前星球/角色色板匹配。
- [ ] 可碰撞对象与背景可区分。
- [ ] 必要动画切分可行。
- [ ] 文件命名和尺寸正确。
- [ ] 来源与许可已记录。
- [ ] 已放入真实 640×360 场景截图审查。
