# 04 — Demo Scope / Demo 范围

## 1. 产品阶梯

| 里程碑 | 目的 | 内容规模 | 对外定位 | 当前状态 |
|---|---|---|---|---|
| M0 Playable Spine | 证明完整游戏结构成立 | 1 站、1 船、1 星、1 主线订单 | 内部试玩 | **Done（2026-07-24）** |
| M1 Four-Planet Demo | 证明多星球差异、成长与主线弧线成立 | 1 站、1 船、4 星、支线与回访 | 可分享 Demo | **Planning Ready** |
| M2+ Full Game | 扩展主线、支线、回访与结局 | 更多星球和终局系统 | 后续决定 | 愿景阶段 |

M0 是 M1 的技术和体验准入门槛。M1 不重做 M0，而是在完整回归保护下扩展内容与成长。

## 2. M0 — Playable Spine

### 状态

**Done。** Gate A–D 已通过，`6/6` 阶段与 `35/35` 任务完成。

### 已完成流程

```text
主菜单
→ 边境快递站与老皮教程
→ 赤砂星订单与飞船配置
→ 第一人称驾驶舱旅行
→ 星系外缘、陨石、轨道、大气、雷暴、低空管制、准备走廊与着陆
→ 赤砂星居民维修场剧情
→ 结算、返站、纪念物
→ 保存与继续游戏
```

### M0 保护范围

- 大厅接单、老皮教程、模态 UI。
- 驾驶舱热点、旅行状态与对话跳过。
- 飞船手感、重力补偿、有限倒车、Boost、持续激光和统一伤害。
- 赤砂星完整路线、canonical 高度、雷达、着陆与检查点。
- 目的地剧情、结算、返站、版本化存档和继续游戏。

M1 修改共享系统时必须运行 M0 完整闭环回归。

## 3. M1 — Four-Planet Demo

### 状态

**Planning Ready。** `CODEX_GOAL.md`、`M1_DEVELOPMENT_TASKS.md`、技术增量、Gate E–I 与三颗新增星球 Planet Packet 已建立。实现尚未开始，第一项任务为 T-100。

### 3.1 Demo 目标

M1 要证明游戏不只是“赤砂星的一次性概念”，而是能够让不同自然环境、文明、角色和飞行机制形成一条有序章、发展、中场、高潮和悬念结尾的主线。

玩家完成 M1 后应：

- 记得四颗星球各自的自然、人文和飞行身份。
- 关心老皮和至少数名星球角色的后续。
- 看见首单和后续选择造成的世界变化。
- 理解模块、关系、许可、图鉴和站点变化的成长意义。
- 明确知道中继网不是银河外卖公司建造。
- 仍想继续追查创造者、用途和老皮的关系。

### 3.2 主线顺序

```text
赤砂星首单（M0 已完成）
→ 白噪星
→ 赤砂星回访与成长中场
→ 穹林星
→ 群潮星高潮
→ Demo 悬念结尾
```

#### 赤砂星

- 教程、公司档案矛盾、低空管制雷达和第一块中继线索。
- M1 必须回访，展示冷却系统、伊娅和居民维修场的可见变化。

#### 白噪星

- 冰原、冰洞、极光、电磁暴雪和较强重力。
- 记忆档案文明与“谁决定记忆被保存”的冲突。
- 主线要求确定获得的特高压电屏蔽罩。
- 揭示中继网早期历史记录。

#### 穹林星

- 巨树、树洞、藤蔓、孢子和飞行生物。
- 生态文明与运输需求的边界。
- 活性货物吸引生物，形成非战斗路线压力。
- 武装/和平配置影响信任、通行或内容。

#### 群潮星

- 海洋、岛屿、横风、潮汐、移动平台和天气塔。
- 城邦围绕公共天气与航路控制产生冲突。
- 多星球线索交汇。
- 明确证明中继网不是公司建造，并形成 Demo 高潮。

### 3.3 每颗新增星球最低包

- 1 条完整进入/配送路线。
- 1 件专属剧情货物。
- 1 个独特环境或文明飞行机制。
- 1–2 名核心 NPC。
- 1 个小型目的地区域或高质量场景式交付。
- 1 个纪念品或图鉴条目。
- 1 个回访变化种子。
- 独立色彩、背景层、环境音和主题动机。
- 完整接单、配置、旅行、飞行、交付、结算、返站和保存流程。

### 3.4 订单与内容预算

#### 主线/章节订单

目标约 5 份：

1. 赤砂星首单（M0 已完成）。
2. 白噪星主线。
3. 赤砂星回访章节。
4. 穹林星主线。
5. 群潮星高潮订单。

#### 支线

目标约 4–6 份：

- 每颗星球至少一项可选角色或探索内容。
- 至少一份加急订单，超时只降低报酬。
- 至少一份正式低空投放订单。
- 支线可复用路线阶段、短路线或不同交付方式，不批量制作独立长关卡。
- 一次仍只携带一份订单。

#### 驾驶舱与站点

- 每次主线旅行至少一个新驾驶舱内容。
- 快递站至少三次可见状态变化。
- 至少一次旧角色和旧地点回访。

### 3.5 M1 新增系统

允许加入：

- M0 schema v1 → M1 schema v2 迁移。
- 多星球解锁、章节和回访状态。
- 主线/支线订单、加急计时和部分报酬。
- 低空投放作为第二种正式交付方式。
- 飞船模块库存、购买和剧情模块。
- 快递站功能与视觉升级。
- 星球关系和通行许可。
- 图鉴、纪念品墙和客户历史扩展。
- 武装/和平倾向反馈。
- 局部选择和 Demo 结尾变量。

仍不加入：

- 完整敌人战斗、地表射击或海盗 AI。
- 多飞船购买和船员管理。
- 程序生成星球、路线、NPC 或词条。
- 多单同时配送。
- 复杂贸易、贷款、维修债务和保险。
- 开放宇宙或任意星球着陆。
- 正式结局和 95% 图鉴隐藏结局。
- 全配音、平台 SDK、成就、云存档和联机。

### 3.6 M1 预期时长

- 首次主线体验目标约 2–4 小时。
- 另有少量支线、回访和收集。
- 这是范围估计，不是通过空白飞行、重复对话或刷取强行满足的时长指标。
- 单颗主线星球横版进入仍以约 1–3 分钟为工作基准。

## 5. M1 人工试玩门

### Gate E — 白噪星

确认第一颗新增星球不是赤砂换皮，屏蔽罩、强重力、电磁暴雪和档案文明成立。

### Gate F — 成长与回访

确认赤砂变化、支线、低空投放、升级、许可、图鉴和站点成长成立。

### Gate G — 穹林星

确认树冠空间、生态压力和武装/和平反馈成立。

### Gate H — 群潮星

确认高潮飞行、城邦冲突、中继揭示和 Demo 结尾成立。

### Gate I — M1 完整闭环

确认四星差异、2–4 小时主线、支线/回访、存档迁移和可分享 Demo 候选成立。

每个 Gate 未通过前不扩展下一大内容层。详细试玩路径见 `Docs/12_M1_ITERATION_GATES.md`。

## 6. 内容生产规则

每颗星球按顺序完成：

```text
Planet Packet
→ Order Packet
→ Character Packet
→ Resource 与本地化
→ 路线灰盒
→ 独特机制
→ 驾驶舱与到达剧情
→ 结算、关系、许可和回访种子
→ 视听占位
→ 自动回归
→ Human Check
```

M0/M1 采用手工路线和固定危险。允许辅助脚本摆放内容，但不建立程序生成游戏系统。

## 7. M2+ 远期方向

以下只保留愿景，不进入 M1 活动任务：

- 更多主线和支线星球。
- 可选海盗追逐或护航。
- 更多交付动作。
- 更深入的飞船和站点成长。
- 主线结局与约 95% 图鉴隐藏结局。
- 主线后持续订单和宇宙秘密探索。
- 可能的站点迁移或受损剧情。
- 多平台发行。

## 8. 范围变更规则

新增功能先判断：

- **M1 必要：** 缺少它无法证明四星差异或主线弧线。
- **M1 打磨：** 改善体验，但不阻塞当前 Gate。
- **M2+：** 不影响可分享 Demo 成立。

新增 M1 任务必须写明玩家价值、范围、明确不做、验收、依赖和 M0 回归影响。不能只增加范围，不说明替代、延后或成本上限。
