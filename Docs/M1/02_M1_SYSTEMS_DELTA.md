# M1 Systems Delta / M1 系统增量

本文只描述相对 M0 的新增或扩展。M0 已通过的飞行、模态、伤害、检查点、存档备份与场景流合同默认保持。

## 1. 存档与进度

新增：

- schema v2 与 v1 迁移。
- `main_story_chapter`。
- `unlocked_planet_ids`。
- `planet_relation_values`。
- `planet_permission_ids`。
- `codex_entry_ids`。
- `souvenir_ids`。
- `completed_side_order_ids`。
- `station_state_level` / `station_upgrade_ids`。
- `ship_upgrade_ids`。
- `revisit_state`。
- `demo_ending_flags`。

不新增多存档槽、云存档或飞行节点序列化。

上述字段的运行时真相仍在 `GameStateModel`。章节、星球、关系、许可、图鉴、
纪念品和回访统一通过公开 API 修改；`M1ProgressRules` 只提供无状态白名单与准入
评估，`SaveService` 继续捕获同一批 schema v2 字段。

## 2. 多星球导航

- 导航由 PlanetDefinition、章节、许可和模块共同决定。
- 正常订单终端与驾驶舱导航从独立 `m1_data_registry.tres` 读取完整目录；
  `m0_data_registry.tres` 只保留为冻结回归夹具和显式兼容注入，不再是正常场景入口。
- `M1CatalogModel` 以无状态投影统一生成订单目录、星球目录、锁定原因和模块状态；
  UI 只保存当前选中项，不复制章节、解锁、订单或航线真相。
- 星球注册与路线可玩性分离：赤砂回访在 T-112 完成正式短路线闭环后为
  `PLAYABLE`；白噪、穹林、群潮在各自正式订单流程完成前仍是
  `REGISTERED_ONLY`，没有正常玩家可选场景路径，也不借用赤砂路线。T-120
  可以提供隔离路线调试夹具，但不改变这个正式内容门禁。
- 未解锁星球可以显示轮廓与解锁原因，但不能选择。
- 主线顺序默认固定：赤砂回访 → 白噪 → 穹林 → 群潮。
- 支线只在对应章节和关系条件满足时显示。
- 驾驶舱仍不自由驾驶星图。
- 当前白噪导航解锁要求精确完成赤砂屏蔽改装回访、到达白噪章节、赤砂已解锁且
  已拥有特高压电屏蔽罩；真正的出发资格还要求把模块安装到 Defense 槽。穹林与
  群潮各要求前序章节和前一颗星球，不允许越级解锁。
- T-114 将白噪准备状态集中为“前序未完成 / 模块未获得 / 已拥有未安装 /
  资格满足但正式航路未开放”四种只读投影。订单终端、模块工作台和驾驶舱共同
  消费该结果；导航节点解锁不等于订单可接或航路可飞。

## 3. 订单模型

- 一次仍只允许一份 active order。
- `OrderDefinition` 增加 `MAIN / SIDE / REVISIT`、`LANDING /
  LOW_ALTITUDE_DROP`、章节与解锁条件、加急参数、关系/许可/图鉴/纪念品奖励及
  `UNIQUE / REPEATABLE / ARCHIVED_ONLY` 重复策略。
- 订单也使用 `REGISTERED_ONLY / PLAYABLE` 内容就绪状态。Packet 中尚未落地剧情
  与路线的 M1 订单可以进入开发目录，但不能接取、确认配置或开始旅行；玩家看到
  稳定的本地化获取路径，不看到内部 ID。
- 持久状态统一为 `AVAILABLE / ACCEPTED / COMPLETED / FAILED / ABANDONED /
  ARCHIVED`；只有 `ACCEPTED` 占用 active order 槽位，存档中也只允许一个
  `ACCEPTED`。
- 主线与回访订单不可误放弃；失败时保持 `ACCEPTED`，由既有检查点/重试流程继续，
  不制造主线死档。
- 支线可放弃、失败或以降低报酬的完成结果表达部分成功。`REPEATABLE` 只允许
  `FAILED / ABANDONED → ACCEPTED` 的显式重接；任何 `COMPLETED` 订单都不能再次
  接取或重复发奖。
- `ARCHIVED_ONLY` 用于只记录历史而不进入 active order 的条目，不是可接任务。
- 支线失败不撤销主线章节、模块或星球资格。
- 接受条件统一消费 T-102 的章节、星球、许可和模块状态；订单完成通过
  `GameStateModel` 的单一入口原子应用信用点、关系、许可、图鉴、纪念品、飞船
  模块所有权、导航节点、站点状态、章节、回访状态和完成标记，并写入奖励幂等
  账本。导航节点奖励使用 `planet_unlock_rewards`，只有预测结算后的全部准入
  条件成立时才允许事务提交。
- `required_completed_order_ids` 表达必须真实完成的前序订单，不允许只靠章节或
  剧情标记越级。赤砂回访同时要求 M0 实际订单 `order_red_sand_m0` 已完成。
- T-112 的赤砂回访使用统一结算入口的受校验附加参数：本地保留记录分支可增加
  一次赤砂关系奖励，剧情奖励模块可在同一事务中写入所有权并安装到合法槽位。
  附加关系、模块引用或槽位不合法时，结算在信用点和任何进度变化前整体拒绝。
- 章节、模块、站点和回访奖励在任何数值变更前统一校验；非法章节跳级或未知
  ID 会拒绝整次结算，不产生部分奖励。
- 订单终端按“当前主线 / 可选支线 / 下一步线索 / 历史”分层：active order 固定
  置顶，同一时刻最多一个当前主线，未发现的支线不泄露名称。`COMPLETED /
  ARCHIVED` 历史由同一注册表与订单状态投影为逐条可选的只读详情，不提供接取；
  若未持久化详细飞行结算，只显示已知订单资料、剧情选择摘要和“详细飞行结算
  未保留”。M0 兼容 alias 在投影前归一化，不生成重复历史。
- 不建立随机刷新、每日任务或无限委托板。
- 图鉴和纪念品奖励引用类型化 `CodexEntryDefinition` /
  `SouvenirDefinition`，注册表不再用平行手写 ID 列表维护同一内容。
- M0 文档 canonical ID `order_red_sand_cooling_core` 仅作为历史 alias 指向实际
  `order_red_sand_m0`，不会生成第二份可接订单。

## 4. 支线计时与报酬

加急支线可以配置：

```text
target_seconds
grace_seconds
minimum_reward_ratio
relation_bonus_on_time
```

规则：

- 只有 active 的加急订单累计 `OrderRunState.elapsed_time`；非加急订单不累计。
- `elapsed_time <= target_seconds` 时保留全额信用点及准时关系奖励；随后在
  `grace_seconds` 内线性降至 `minimum_reward_ratio`，继续超时也不低于该下限，
  不直接硬失败。
- 对话、帮助面板和系统暂停均暂停计时。
- 检查点重试保留同一计时；完成后由 `reward_applied_order_ids` 阻止重复增加奖励。
- 非加急订单不显示倒计时压力。

T-108 的运行时落地保持单一计时入口：

- `App/PersistentUI/ExpressOrderHUD` 是跨场景保留的唯一驱动；每帧只由组内权威
  实例调用一次 `GameStateModel.advance_active_order_time()`，阶段场景和各自 HUD
  不再另行累计。
- 驱动使用 `PROCESS_MODE_ALWAYS` 观察持久对话层、飞行帮助层和
  `SceneTree.paused`，冻结时仍可刷新“已暂停”反馈，但不增加 `elapsed_time`。
  对话与帮助打开时由模态面板内提示接管反馈并隐藏紧凑 HUD，避免边缘残片；
  单纯系统暂停时紧凑 HUD 保持可见。
- 场景切换、检查点与 `R` 重试只改变场景/飞行状态，不重置计时；schema v2
  继续保存该字段。读取存档后从已保存值继续，不根据系统时钟补算离线时间。
- 紧凑 HUD 固定为两行，区分全额、宽限、保底和暂停，并显示 `mm:ss` 与当前
  信用点比例；非加急订单整块隐藏。订单终端只对加急订单显示目标、宽限、最低
  比例及“超时不会直接失败”的说明。
- 结算严格按“基础信用点 → 货物完整度修正 → 加急时间修正 → 最终信用点”计算。
  `OrderSettlementCalculator` 生成完整结果，`GameStateModel` 只提交已经计算好的
  最终值，不再重复乘时间倍率；准时关系奖励仍由统一完成入口和奖励账本保证只
  发放一次。

群潮支线“风眼前的灯”在 T-108 仍为 `REGISTERED_ONLY`；上述流程只通过独立测试
夹具验证，不提前开放路线或玩家接单入口。

## 5. 第二种正式交付：低空投放

M1 的低空投放先使用固定、宽容接收区：

- 玩家进入高度、速度和水平位置窗口。
- 按统一 Input Map action 释放货物。
- 成功：落入核心接收区。
- 部分成功：落入外圈，降低报酬/关系。
- 失败：错过区域或货物损坏，可重试或放弃支线。
- 投放后同一货物不可重复释放。
- 不做军事投弹、复杂弹道或移动敌对目标。

T-107 的独立 `Delivery Lab` 先锁定以下可调原型基线：

- 有效高度 `90–220 m`，有效水平速度 `90–240 m/s`。
- 核心接收区为中心 `±110 m`，外圈为中心 `±220 m`。
- 货物以 `120 m/s` 的固定下降速度运动，继承飞船 `65%` 的水平速度；预计落点
  只由释放位置、高度和水平速度确定，不读取随机数或刚体碰撞。
- 外圈部分成功保留 `75%` 货物质量和 `65%` 报酬；核心成功为全额，外圈以外
  为可重试失败。
- 高度或速度不合法时货物不会被释放；合法释放后单货物门闩立即关闭，重复键鼠
  输入只给出原因，不产生第二件货物或第二次结算。
- `R` 从 Delivery Lab 检查点同时恢复飞船、货物、预计落点和投放结果。该场景
  不写入活动订单、信用点或穹林星正式路线状态。

首次正式使用：穹林星支线“孢子季急投”。

## 6. 关系、许可与玩家方式

关系值是小型叙事状态，不是可刷声望条。

影响：

- 后续对白。
- 部分支线和回访入口。
- 许可或便利路线。
- 图鉴文本。
- Demo 结尾变量。

来源：

- 主线局部选择。
- 支线结果。
- 武器封存/保留。
- 货物状态和交付方式。

不得通过重复同一订单无限刷关系。

M1 运行时关系范围集中为 `-2…+3`。每次正常关系变化携带唯一事件 ID，已应用事件
随 `story_flags` 保存；重复事件、到达边界后的无效变化和重复许可均不再次发出
持久化变更。

## 7. 飞船成长

### 特高压电屏蔽罩

- 白噪星主线资格模块。
- 降低电磁干扰和高压环境风险。
- 不替代普通护盾资源。
- 由赤砂回访确定获得。
- T-110 将它登记为赤砂回访唯一、免费且不可重复的主线奖励；T-111 已落地所有权
  与安装分离、schema v2 往返恢复、能力标签读取和飞船可见屏蔽轮廓。
- T-112 在赤砂回访正式结算时原子发放并自动安装该模块；玩家之后仍可在正常
  工作台卸下或重新安装，同时原子解锁白噪导航节点，不建立不可逆的隐藏配置。
- 模块必须实际安装在 Defense 槽后才生效；仅拥有模块只解锁后续目录/导航资格，
  不能通过白噪出发前检查。
- 当前可调工作基线为高压资源伤害乘数 `0.60`、电磁干扰乘数 `0.45`。高压伤害
  缩放后仍进入 M0 的普通护盾优先伤害入口，不增加第二条“特殊护盾”资源。
- 配置工作台会区分“尚未获得”“已拥有未安装”“已安装”，并明确剧情模块由
  对应主线固定获得，不提供购买、随机掉落或刷取路径。
- 槽位显示始终以真实已安装模块或当前可管理的已拥有模块为身份来源；“主线必需 /
  订单推荐 / 本次订单不要求”是独立订单角色，“已安装 / 已拥有未安装 /
  尚未获得”是独立状态。订单角色不得覆盖模块名称、说明或已拥有模块的装卸按钮，
  必需配置检查仍只消费订单 `required_modules`。

### 生物信号隔离舱

- 降低穹林星货物吸引生物的范围/频率。
- 不使玩家完全免疫生态风险。

### 横风稳定器

- 降低群潮星横风扰动。
- 不自动驾驶、不取消风向判断。

配置界面继续保持少量明确槽位；不引入随机品质与复杂科技树。

## 9. 星球独特机制扩展方式

核心飞船脚本不得堆叠 `if planet_id == ...`。

推荐：

- `FlightEnvironmentProfile`：重力、阻力、风、能见度。
- 小型危险组件：电磁干扰、生态吸引、横风区域。
- `FlightRouteDefinition`：阶段、检查点、背景和交付目标。
- 模块 capability tags：环境适应能力。
- 独立纯逻辑模型：可自动测试的危险与判定。

M0 的统一伤害、HUD、帮助、重试和 SceneRouter 继续复用。

## 11. 图鉴与纪念品

基础类别：

- 星球。
- 人物。
- 货物。
- 纪念品。
- 异常信号。

原则：

- 未解锁条目不剧透。
- 图鉴记录人物和选择结果，而非只列百科。
- M1 不要求 100% 收集。
- 约 95% 隐藏结局属于完整游戏远期，不在 M1 实现。

T-106 基础实现：

- `CodexCatalogModel` 是无状态只读投影，输入为 M1 注册表与
  `codex_entry_ids / souvenir_ids`；分类、列表和详情 UI 不直接改写进度。
- `hidden_when_locked = true` 的条目完全不进入结果；允许保留锁定位的条目只显示
  通用“未知记录”，不暴露标题与说明。
